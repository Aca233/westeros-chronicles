# 角色扮演上下文与模型体系重构方案

日期：2026-09-07。状态：核心运行时已于 2026-09-08 接入；发布验证边界见 [实施状态](../IMPLEMENTATION_STATUS.md)。用户已明确优先方向：角色扮演。

后续扩展：[全游戏机制审视与重做决策](../gameplay-overhaul-2026-09-07/README.md) 已覆盖 80 项机制，并更新默认建角、检定模式、特质被动、耐久等具体取舍；本套文档继续作为上下文、认知、记忆与模型协议的技术基础。

## 1. 设计结论

让玩家扮演一个具体的人：有来历、有关系、有欲望、有不愿付出的代价；其他人会记住他的言行，却未必理解他的本意。

保留现有“模型提案 → 程序结算 → 正文生成 → 原子提交”的骨架。重构重点是补全场景、认知、社会事件和长期记忆，使文字与世界状态形成完整闭环。世界资料、六项属性、装备和地图已经提供了足够厚的基础；下一阶段最有价值的工作是让这些基础实际改变人物的选择与反应。

这里的“完善”以可检验的标准定义：世界不自相矛盾，人物不集体失忆，秘密不会自动广播，失败有可信后果，玩家保有角色决策权，长期游玩仍能维持连续性。文笔质量需要持续试玩与评测，任何提示词都不能单独保证零失误。

## 3. 当前机制审视：值得保留的部分

| 已有基础 | 对角色扮演的价值 | 决策 |
|---|---|---|
| 两阶段回合与原子提交 | 正文成功后状态才正式落地，失败不会留下半个世界 | 保留，补事务内人物投影与叙事验证 |
| 静态资料 + 稀疏世界覆盖 | 原作人物可在同一个周目中改变命运 | 保留，不复制整套世界到提示词 |
| 人物稳定 ID、头衔与物品归属 | 同名人物可区分，传家剑不会凭文字被复制 | 保留，展示名和可操作身份分离 |
| 多维关系 | 信任、恐惧、尊重、人情可以产生不同反应 | 保留，改为有证据的增量与定性表现 |
| 装备、部位伤势、旅行 | 身体、物资、距离成为选择的真实约束 | 保留，减少无意义操作次数 |
| 世界事件、可见性和原作分歧 | 提供长期因果与信息不完整的基础 | 加固传播渠道、受众、时间与前置条件 |
| 模型适配器、取消、调试轨迹 | 模型供应商可替换，故障可定位 | 保留，加入能力档案、用量、终止原因与版本 |

## 5. 角色扮演的核心循环

**身处情境 → 理解有限信息 → 以角色身份行动 → 遭遇他人反应 → 付出代价或建立关系 → 留下可被再次触发的记忆。**

每次行动至少回应玩家的表达；可以只是安静的观察、短暂沉默或日常相处。不要硬性要求每回合制造危机、关系涨跌或世界事件。一个完整场景应在信息、关系、资源、处境或承诺上留下可感知的变化，也允许玩家主动离开无进展的谈话。

### 5.1 玩家角色：身份与自主权

- 开局保存身份、社会地位、公开履历、重要关系、已知事实与可选私人目标。私人目标由玩家填写或选择，不由模型突然揭露。
- 原作人物继承基线中的真实亲属、过往与身份；玩家可以改变此后的行事方式。自建人物通过实际履历建立人脉。
- 特质决定容易注意什么、什么行为更费力、别人如何理解他；不强迫玩家说台词或采取行为。
- 玩家写出的台词可忠实融入正文。未表达的誓言、同意、情感认定、杀意和人生目标不得替写。
- 角色可以被误解、威胁、拒绝或依法限制自由；这些是世界对其的行动。系统仍把回应、屈服、反抗或沉默的选择交还玩家。

### 5.2 NPC：稳定欲望、有限认知、可变策略

每位当前关键人物只有一张紧凑运行卡：长期价值观、当前目标、畏惧的代价、与玩家的关系依据、已知事实/误解、尚未履行的承诺、当前情绪与表达方式。性格与动机须有静态资料或周目事件来源。

NPC 不为每句赞美加好感，也不因一次成功检定突然背叛一生信念。成功可以换来解释、有限让步、暂时容忍或一个有条件的机会。红线与现实利益决定可谈判空间。

第一版最多激活少量场景核心人物，其他人用规则或摘要维护；没有必要让 2,241 名人物每回合都调用模型。非在场人物依赖通信、截止日期、到达事件或自身议程推进。

### 5.3 社交：围绕诉求与筹码

一次社交行动记录：向谁、请求什么、用什么理由/证据、提供何种交换、在谁面前说、承受什么风险。

关系保留现有好感、信任、恐惧、尊重、吸引、人情维度，但首版只为本场景实际相关维度更新；数值在后台支撑一致性，正文与卷宗主要呈现有根据的态度和经历。变更使用事件驱动的增量、上限与冷却，禁止模型无依据整张覆盖关系。

承诺必须包含承诺者、受益人、内容、成立条件、到期时间、知情者、状态；“我会考虑”不是承诺。重复许诺不能无限刷关系，履约与违约比口头表态更有权重。

### 5.4 调查与秘密：可玩的信息差

线索具有来源、获取方式、证明范围与可信度。NPC 说某人下毒，只证明他提出了这个指控；真相需要其他证据或权威事件确认。

调查失败可以导致时间损失、证人戒备、信息不完整或提高暴露风险。相同条件下重复同一个问题复用已知结果；只有方法、证据、对象或处境发生实质变化，才重新判断。

玩家本人熟悉原作不等于角色知道未来。带超游信息的输入允许作为猜测提出，必须经过游戏内验证才能升级为角色知识。

### 5.5 冲突与战斗：动作、立场和退出机会

六项能力与现有 D20 保留。先判断行动是否可能，再判断是否存在真正的不确定性与失败代价。普通行为无须掷骰；不可能行动说明障碍，不通过大成功突破物理或身份限制。

首版保留二元检定以减少变量；成功轨也可有预告的代价，失败轨也可获得局部信息。后续仅在试玩证实价值后再引入“有代价的成功”作为独立结果等级。

战斗围绕近身位置、对手意图、装备、伤势和退路组织。一次自由行动对应一个有意义的战术节拍，不对每一次挥剑都强制堆叠骰子。致命风险应在行动前通过角色能察觉的信号呈现。

### 5.6 旅行、时间与世界主动性

旅行服务于“去哪里、见谁、错过什么、愿付多少代价”。保留路线与真实耗时，允许跳过平静路程，只在遭遇、补给、消息或决策节点进入细场景。

采用动作时间、场景时间、旅途时间三级推进；世界日期不能靠正文暗自跳跃。可在现有日期之上增设日内时段/分钟，不把每次谈话都当成一天。

原作时间线改为具备前置条件的压力节点：到期检查位置、存活、动机、资源与依赖。前置改变后允许延后、替代或取消；节点发生与玩家听闻分开结算。到期调度按模拟时间触发，不按玩家发送次数奖励或惩罚。

### 5.7 经营、地图与装备的取舍

| 体系 | 当前基础 | 角色扮演优先的调整 |
|---|---|---|
| 经营 | 金钱、资产、头衔、据点 | 优先处理俸禄、借款、欠粮、封臣请求和人情债；完整税收产业模拟延后 |
| 地图 | 丰富地点、政治图层、旅行 | 地点详情突出“为何去、能见谁、已知风险、耗时”；地图细节按需查看 |
| 装备 | 严格穿戴与容器规则 | 常用换装可保存合理预设；物品在场/归属仍由程序验证 |
| 人物卷宗 | 多页签静态与动态信息 | 首屏突出最近变化、共同经历、未了承诺；限制秘密与精确隐性数值 |
| 选项 | 固定三分支与属性倾向 | 2—4 个按当前诉求生成的建议；保留自由输入，允许拒绝、追问、退出 |
| 成长 | 属性/特质命令 | 重复练习积累、重大经历形成里程碑；普通交谈不刷属性或永久特质 |
| 死亡 | 致命伤导致结束 | 第一版保留明确终局；继承人续玩另立功能，不能靠正文隐式换主角 |

选项差异应来自价值与代价。例如同一项请求可以“公开表态，承担声誉风险”“私下询问条件，消耗时间”“暂不答应，保留立场”；不要求每幕都出现战斗、阴谋和外交各一条。

## 6. 最先做成的竖切场景

用同一名玩家与一位有既有关系的 NPC，完成“私下求助 → 有条件承诺 → 被第三人误解 → 调查来源 → 履约或违约 → 十回合后再次见面”。

这段流程能同时验证上下文、对白、认知、记忆、关系与时间，所需世界范围很小。奈德视角可以检验原作身份与政治关系，自建人物视角可以检验弱势身份；琼恩与丹妮莉丝开局用于检查是否仍残留“人人都有封臣与佩剑”的模板。

## 7. 技术参考与适用范围

精简高价值上下文、在需要时检索、保留结构化长期笔记，是可借鉴的工程原则。本文把这些原则改造成有受众和事务边界的游戏合同；来源没有为本项目的预算、schema 或玩法背书。[Anthropic：Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

模型调用优先采用少量职责明确的固定步骤，复杂度由失败案例驱动增加；本文默认两次前台调用，关键场景按需增加隔离的 NPC 决策。[Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

# 分阶段实施与验收

状态：核心运行时已接入，尚未进行真实模型长局与真人发布验证；逐项状态见 [实施状态](../IMPLEMENTATION_STATUS.md)。实施以可玩的完整场景推进，不以新增模块数量衡量完成度。

## 1. 交付顺序

### 阶段 0：锁定结果与认知边界

目标：现有角色扮演不再因协议容错、在场推断和成败轨混用而发生不可信变化。

| 修改位置 | 动作 | 完成标准 |
|---|---|---|
| `src/services/turn/diceRequest.ts` | 区分 missing/invalid/valid-empty；严格布尔与判别联合 | 坏协议报错；空失败轨合法；不能默认为不检定 |
| `src/store/useGameStore.ts` | 提取纯函数选择结果轨，去掉失败回退成功 | 失败命令与失败意图一起选择，成功副作用不可达 |
| `resolutionTypes.ts`、`resolutionProtocol.ts`、`worldPreparation.ts` | 全结果对象分轨，新增统一执行门槛 | 行窃失败不会转移资产；复合行动依赖不被拆散 |
| `worldTurnContext.ts`、`characterCommandValidator.ts` | 分离提及、同地、在场与通信 | 提到远方人物不能伤害/结婚/移动该人物 |
| `settlementFacts.ts`、`worldEventVisibility.ts` | 显式受众与来源，隔离未来压力 | 正文数据包没有未来节点或未知事件；不能以 public 缺省绕过 |
| `characterMemory.ts` | 修复零槽位并禁止混受众压缩 | 零槽位不返回全部普通记忆，私密内容不扩大受众 |
| `api.ts` | 无效分支使用能力验证后的保守建议 | 没有佩剑/封臣时不生成拔剑/召兵选项 |

这一阶段可以继续兼容旧 XML，但容错只能修格式，不可猜出游戏结果。优先修正在运行的风险；未接线的压缩函数修复后也不能绕过受众验证直接接入。

已有 `test-dice-request.mjs` 明确测试“缺少判骰默认不检定”和“双轨为空回退普通命令”。这些是需要随新合同一起修改的旧行为断言，不能为了维持旧测试全绿保留不安全回退；替换时同时加入合法空轨与非法缺轨的区别测试。

### 阶段 1：场景状态与上下文编译器

建立 SceneState、TurnWorkingSet、ContextPacket/Manifest；各阶段使用显式受众和预算。保留 `promptBuilder.ts` 外部入口，内部逐步委托新编译器。

正文前将 `settled.characterEvents` 叠加到同一事务视图，和 `worldRuntime`、玩家物品、时间一起投影。明确哪些数据是已提交基线，哪些是本回合待提交变化。

旧、新编译器先做本地 shadow 对比，只生成结构与 manifest，不双发付费模型请求。对比人物集合、秘密过滤、事实 ID、预算与漏召回。确认后仅切换一条默认路径，避免两套上下文长期各自维护。

完成标准：读取正确的人和事实；关键约束不会因 token 预算被裁掉；同一 revision/配置编译结果稳定；调试界面解释所有召回与省略。

### 阶段 2：社交事件、认知和承诺竖切

实现最小社会事件集、个人知识投影、请求/答复/承诺生命周期与关系增量规则。第一版只支持当面交谈和已有旅行能力，不同时扩展全世界谣言经济。

将 `resolveCharacter(...).knowledge: []` 替换为实际事件投影。把角色当前目标由明确的基线/周目事件装配到人物卡，不能用模型临时推测的隐藏欲望作为权威。

社会事件与世界变化进入同一原子提交；保存发言语义及与正文中的实际措辞对齐，下一拍可回看。场景与认知存档 schema 升级在此阶段完成。

完成标准：私下保密样例可以实际游玩；旁观者是否知情、明早是否履约、十回合后是否提起，都由事件决定。无关系数值变化的交谈仍可留下承诺和未答问题。

### 阶段 3：长期记忆与低成本召回

建立来源索引、中文词法检索、实体/承诺优先召回、按受众分区摘要、任务队列及失效机制。先验证 10/50/100 回合场景，不急于引入向量数据库。

回合提交后，摘要任务以源事件集合与分支版本为条件写入。撤回、读档、导入、复制分支时明确历史可达性与缓存失效。源记录保留，不把生成摘要当作唯一存档。

完成标准：召回十回合前的承诺和五十回合前的重大背约；不会从废弃分支召回事情；摘要服务不可用时继续游戏；上下文大小不随回合数线性增长。

### 阶段 4：正文、选项和模型运行层

切换新正文协议与提示词，使用能力驱动的 2—4 个建议行动。增加适配器结构化返回、usage、finishReason、增量正文解析、角色预算与失败修复。先通过同一模型前后对照，再考虑不同角色配置不同模型。

对普通交谈、关键谈判、旅途、冲突分别评测篇幅和节奏；保留玩家自由输入。重要承诺/秘密加入语义检查。移除 `<think>` 的存档与 UI 依赖，调试页改为“采用了哪些事实/规则”的简短可审计说明。

完成标准：正文明确回应玩家，有角色差异，关键事实与对白语义一致；失败重写不重新掷骰；流式预览不被提前写入长期记忆。

### 阶段 5：按时间推进的世界与玩法扩展

增加消息送达、NPC 议程、具有前置条件的原作压力、旅行场景选择与关系里程碑。世界处理按模拟时间和事件订阅运行，同一时点任务有稳定顺序和执行次数上限。

可采用“调度已批准 NPC/世界事件 → 形成新的下一拍结果 → 玩家可见消息/场景”流程。调度不能直接给正在展示的正文补写过去未发生的事件，也不能在用户暂停游戏时擅自推进模拟时间。

完成标准：角色在玩家没有逐句催促时仍会按承诺与目标行动；事件经合理渠道到达玩家；旅行可跳过无事路段。先验证十几个关键角色与局部世界，再扩大活动范围。

## 3. 存档迁移与回滚决策

当前格式已升级为 10。社会/认知/场景、通信、议程与委派成为权威状态，数据库 schema 通过 Dexie v4 执行一次性迁移。

已提供格式 9 到 10 的一次性保守迁移；迁移遵循：

1. 备份原存档，迁移创建新存档位/新 run；保留原档以便恢复。
2. 保留旧世界状态、已提交事件、人物事件与历史正文；补齐 ID 映射和源修订号。
3. 当前场景只从可验证地点、已有明确在场证据建立。资料不够时开一个中性过渡场景，不把旧正文提过的人全认作在场。
4. 旧 ADD_MEMORY 作为 legacy 来源导入，保留旧受众；无法确认来源或可见性者不进入自动模型召回。
5. 不从全部旧小说中自动铸造秘密、婚约、债务等新权威。可以生成“旧事索引”帮助查阅；有争议内容保持未确认。
6. 导入、撤回、新分支、导出往返测试全部通过后再开放继续游戏。

若项目决定测试版不支持迁移，也必须明确告知“新机制仅新局可用”，保留旧档导出与旧引擎读取方式；不得静默删除或在新 schema 上勉强载入。两种策略实施时择一，不并行维护未经验证的半套兼容层。

Feature flag 按周目固定 `engineVersion/contextVersion`。已写入新权威事件的周目不能直接切回旧引擎；回滚使用原备份存档或兼容读取模式。模型提示词可单独版本回退，但不能输出旧 schema。

## 5. 评估与发布门槛

以下为拟议门槛，当前未达到也未测量。不要把“写进文档的目标”报告成“已经达标”。

| 维度 | 度量方法 | 初始发布标准 |
|---|---|---|
| 状态安全 | R01—R26 对应的确定性断言 | 必需回归 100% 通过，任一秘密泄漏/错轨写入阻止发布 |
| 召回 | 预标注的必需记忆集合与实际上下文比对 | 关键未了承诺/身份/在场证据全部召回；普通相关事件 recall@预算目标 ≥90% |
| 事实一致性 | 已结算事实与正文逐条对照；人工抽审 | 金钱、位置、生死、承诺条件等重大矛盾为零才接受该批次 |
| 玩家自主权 | 标注是否新增玩家台词/决定/情感结论 | 固定发布样例中零重大代行行为 |
| 人物表现 | 双人盲评：动机连贯、角色区分、回应贴切 | 每项 1—5 分，平均目标 ≥4；记录低分例，不只报告平均 |
| 文风 | 场景节奏、重复、对白自然度人工盲评 | 新版优于旧版且无明显变慢/啰嗦的核心场景 |
| 协议成功 | 同一配置固定样例多次运行 | 首次 schema 成功率目标 ≥98%；修复仍失败时绝不提交 |
| 性能与成本 | 分角色 input/output tokens、p50/p95、重试率 | 先建立旧版基线；新版前台默认两调用，所有包满足预算 |
| 长局稳定 | 100 回合固定脚本与存档往返 | 无线性上下文膨胀、跨分支回忆或存档不一致 |

比例报告必须带样本数。例如 60 个场景 × 3 次运行是 180 次，不是 180 个独立长局。按闲谈、承诺、误解、秘密、冲突、旅行分组报告；短样本没出错不证明长期零错误。

最小试玩组合：奈德、自建低地位人物、琼恩、丹妮莉丝各一段至少 10 回合；其中一条扩成 50—100 回合。记录“角色为何这样反应”“我想做但做不到”“系统存在但没有感到影响”的具体回合与输入。

模型裁判可帮助发现候选问题，但硬规则由程序检查，文笔与扮演感必须有人读。不要让写作者自报“我没有泄密”成为通过标准。

## 8. 第一批工作的明确边界

优先完成阶段 0，然后实施“私下保密 → 明早履约 → 再见面”的竖切，覆盖阶段 1—4 的最小路径。竖切达到事实一致、认知隔离、承诺可追溯、正文可读和十回合连续后，再扩充全世界议程、复杂谣言传播和大规模经营。

这能让第一轮重构就产生可见的角色扮演提升，并使每一次新增机制都有真实场景证明其价值。

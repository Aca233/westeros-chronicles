# 维斯特洛编年史：玩法与机制架构 V3

日期：2026-09-08。

状态：完整重构提案，尚未实施，不代表当前运行时能力；本提案不会自动覆盖既有实现状态文档。用户允许删除、替换现有机制乃至重做游戏。本文固定已经明确的偏好：保留 CK3 六项原始属性点数、保留 D20、让不同方法使用适当的主辅属性。其他数值、篇幅和节奏参数均为待验证初值。

## 1. 产品决策

做一款以人物身份和关系为背景、以筹划并执行具体行动为核心、有持续世界后果的单人角色扮演游戏。

玩家控制一个人的行为与承诺。能力、钱财、装备、人手、位置和时间决定可实施的方法；D20 裁定关键不确定性；人物和世界根据已经发生的结果作出回应。自由输入保留，规则允许玩家理解、预测和学习。

三个质量目标同时成立：

- 游戏性：有不同方法、有稀缺投入、有可学习规则、有真实收益和损失。
- 故事性：人物有稳定动机，行为有因果，旧选择能影响新局面，日常关系有停留空间。
- 可玩性：玩家知道正在做什么、能做什么、操作为何受阻；日常管理自动化，失败能继续，场景可以结束。

不把所有对话变成博弈，不把所有人生变成称王，不把机制的存在本身当作乐趣。默认不建设全大陆生产链、全球逐日 NPC 模型调用、完整战棋和自动代际续玩。

## 2. 核心循环与行动尺度

### 2.1 三个循环

1. 场景：观察 → 表达或行动 → 回应或检定 → 局势改变 → 下一选择或离场。
2. 事务：选择目标 → 获取信息 → 选择方法与参与人 → 分配时间和资源 → 执行与调整 → 收束、失败或退出。
3. 人生：经历事务与日常 → 建立关系、专长和地位 → 获得更大的行动空间及责任 → 自选新目标或结束这一阶段。

原型中一件普通事务以 3—6 个有意义场景为内容预算，不作为硬限制。任何事务必须定义完成、失败、退出或暂停条件，禁止无休止追加转折。机会不会全部变成玩家任务。

### 2.2 三类时间尺度

- 对话与现场：分钟或更短；一次输入不是固定一天，也不因为多问一句就消耗一个完整行动点。
- 准备与地方活动：小时；人物在重叠时间内不能执行两项需要亲自参与的工作。
- 旅行与长期安排：小时、天或更长；自动推进到玩家指定终点或下一个必须决策的节点。

无全局体力行动点、无现实时间倒计时、关闭游戏不推进世界。相关截止日期来自真实约定和事态，不为每场闲谈添加压力条。

### 2.3 每次输入的执行边界

纯查询不耗时。确定的小动作直接验证并完成。存在人物回应或风险时进入完整场景。

玩家写“先问价，再决定买不买”，只执行询价。已明确同意的一组动作可以一起执行；新重大代价或新承诺必须停在选择点。技术上的原子提交不等于整个多日行动只有一个结果：已经完成的阶段保持成立，后续失败不能倒抹前面的事实。

## 3. 开局、目标与长期反馈

默认仍用一份 298 AC 世界基线。重点制作奈德、琼恩、丹妮莉丝三个视角及一个落在真实地点的自建普通人物开局；可查询人物不自动成为已验证可玩人物。

开局展示：身份和真实权限、当前地点、熟人、可支配财物、职责、眼前事件。允许选择或留空个人愿望和底线，不把自建姓氏、纹章直接当成爵位与亲属资格。

主要回报包括报酬、物品、联系人、信任、专业成长、组织岗位、居所、授权和解决旧事。它们应打开具体的新方法，而不只是增加一个分数。成为家臣后可以申请资源，成为统治者后可以委派与使用组织预算，同时需要承担对应责任。

承诺、案件与玩家自设打算分开。拒绝任务不会默认扣关系；违背已经成立的承诺才进入后果判断。目标可以修改或放弃，不用任务清空率定义成功。

## 4. CK3 属性与多属性方法

保留 diplomacy、martial、stewardship、intrigue、learning、prowess 的原始点数、教育和特质身份，提供中文领域说明。导入数据与存档原值不能因为换公式被直接压成 0—5 档。

| 属性 | 默认职责 | 不应泛化到 |
| --- | --- | --- |
| 外交 | 谈判、协调、表达、公开场合 | 精神控制、无条件忠诚 |
| 军事 | 组织战斗、布防、战术与指挥 | 替代个人勇武 |
| 管理 | 预算、组织、供应、经营执行 | 被动凭空增加任何入账 |
| 谋略 | 欺骗、隐蔽行动、阴谋与反侦察 | 直接获知别人内心 |
| 学识 | 研究、医学、文书与专业知识 | 万能生存或体力技能 |
| 勇武 | 个人战斗与相关危险身体执行 | 指挥权与军事知识 |

每个 MethodDefinition 固定主属性、可选辅属性、前提与结果范围。同一种方法不因措辞换权重；更换方法允许更换属性。纯单领域行为使用 100% 主属性，不为了多属性而强行平均。

双属性默认：E = 0.7 × A + 0.3 × B。

- 伪造文书：谋略主、学识辅；还必须具备可核实的文字能力、样本和必要工具。
- 买通守卫：外交主、谋略辅；报价、对方利益和接受意愿先验证。
- 安排护送：军事主、管理辅；实际可调用人手是前提。
- 比对账目：管理主、学识辅。
- 骗开门后攀墙：通常是两个有不同风险的步骤，不把文书、欺骗和攀爬平均成一次万能检定。
- 普通决斗：通常直接以勇武为主，不强制加入军事。

资格不能被加权抵消。没船不能靠高学识航海；尚未取得对方同意，不能把高外交等同于签约。

团队由实际执行者检定。助手执行准备动作或提供受限协助，不把全队所有最高属性拼成一个虚构人物；跨人承担完整子步骤时分别使用对应执行者，避免不必要的连续失败门槛。

## 5. D20 的明确规则

### 5.1 公式与精度

默认：T = D20 + E / 5 + M；纯属性行为 E = A。

E 使用全部属性点数，不向下取整、不在 30 点封顶。M 为有事实来源的情境修正，默认合计限制在 −4 至 +4。内部用定点整数比较，避免小数误差；双属性比较可等价写为 50 × D20 + 7 × A + 3 × B + 50 × M 与 50 × DC 比较。

候选环境难度 DC：10、14、18、22。它们是按当前导入分布校准前的起始档，不是最终平衡承诺。环境 DC 来自方法、障碍和现场事实；关键对抗采用 DC = 10 + 对手有效属性 / 5 + 防御处境修正，不额外为同一次对抗掷第二颗骰。相同优势不能同时增加玩家 M 又降低 DC。

保留全部中间点数，但不虚称纯 D20 每点都线性增加胜率。只有 20 个等概率骰面，固定检定的概率以 5% 跳变；中间属性参与余量、辅助贡献与对抗阈值。若以后要求每点恰好增加 1% 胜率，需要用户选择改变为百分制，不能暗中追加第二个随机数冒充纯 D20。

原作极端强者允许在擅长领域稳定成功，不为了强行保持悬念按玩家属性抬高所有难度。极难目标由真实规模、资格或现场障碍限制，不滥用 100 点 DC。

### 5.2 四个结果带

令余量 R = T − DC：

| 条件 | 结果 | 范围 |
| --- | --- | --- |
| R ≥ 5 | 明显成功 | 目标达成，并取得预定义的小优势或减少成本 |
| 0 ≤ R < 5 | 成功 | 达成预定目标 |
| −3 ≤ R < 0 | 接近成功 | 若该方法允许，提供带条件达成或部分成果；否则是较轻失败 |
| R < −3 | 失败 | 未达成，并发生预定义的相关后果 |

自然 1/20 只用于骰面表现，不自动成败、不追加一次灾难随机。大成功由余量体现。接近成功并非总能付钱购买成功；行动定义可以没有这种选项。

例：谋略 23、学识 14，E = 20.3，属性贡献 4.06。有可靠准备 M = 2，DC = 18，骰出 12 得 18.06，成功。无准备则为 16.06，接近成功；两者严格成功率分别为 45% 和 35%。演示概率包含明显成功，不把“接近成功的机会”当成已经达成。

### 5.3 风险与重复尝试

检定前保存目标、方法、执行者、属性、依据、费用、时间、结果范围和可见风险。看得到的确定费用应提前呈现；隐藏难度只显示角色有依据的判断，不能泄露秘密。骰子详情可选展开，无需每次弹窗。

相同目标、方法和事实版本复用同一次 attempt。改写文字不重骰，网络重试不重骰。新证据、真正不同的方法、改变现场或明确新的时间窗口才能创建新尝试。每个准备优势有来源 ID，同一来源不重复计数；简单堆叠相同助手不能无限刷成功率。

## 6. 筹划与执行

事务默认突出目标、已知障碍、参与者、可用手段、资源和下一决定。只对多步骤行动显示计划界面，普通交谈直接进行。

准备的四种收益：打开原先不可行的方法、提供有限修正、降低失败的严重程度、建立撤退或替代方案。不是所有准备都只加命中率。

筹划使用真实时间和投入，不新增通用准备点。玩家能把无风险的小步骤打包，例如“把已批准的费用付给船主并让侍从装车”。若途中出现新争议，停止在该节点。

同时进行的事务占用真实人物与资源。同一人不能在同一时间既调查又护送。默认界面突出一件主动事务和少量相关事项，其他自主目标可保留在日志，不靠无限接任务维持活跃度。

失败可以导致部分成果、曝光、资源损失、关系变化、受伤或错失机会，但不保证总有等价补偿。已经失去的机会可以永久失去；普通失败不自动封死整段人生。

## 7. 人物、关系、伙伴与日常

每名重要人物保存稳定价值、当前目标、知情事实、关系依据、职责和不能随意改变的底线。临时情绪独立于稳定性格，可以衰退。

既有好感、信任、恐惧、尊重等内部维度可以保留作决策输入，但不是可通用兑换的通关阈值。前台展示已知态度与共同经历，不直接暴露全部隐藏分值。请求先根据利益、底线、权限、证据判断是否值得考虑，再裁定不确定的说服效果。

普通闲谈、玩笑、共同用餐与陪伴不要求投骰、不保证加点、不强制引出任务。玩家可以表达动机，模型不能代写玩家的选择、爱情或誓言。

伙伴有专长、职责、空闲与去留意愿。参与一次行动需要同意、雇佣或既有职责依据；常设职责在范围内持续有效，不每次取甲都重新谈判。派人办事记录目标、可支配资源、权限、截止或预计时间与汇报方式；出行、执行、消息与结果必须真正联动。

全大陆静态人物保留查阅基础。当前场景人物深度处理；相关伙伴和对手在到期节点推进；背景人物按事件激活。未登场人物不能仅为制造悬念突然知道玩家秘密。

## 8. 内容、事务与故事推进

重点事务采用人工内容骨架加规则组合：人物、真实事实、冲突、证据、无干预时的发展、结束状态和可替代方法。模型补充对白、细节和合理方法，不凭空更换案件真相或事后生成克制玩家计划的障碍。

每个关键障碍至少具备多种事实层面的解决方式，或明确可以退出。方法不能靠匹配唯一中文关键词；未注册的合理方法先映射为资格、成本、风险和结果结构，再由同一规则验证。不能识别的动作保留为待澄清意图，不自动当作无效或默认成功。

事务有策划的阶段及触发条件，但不是固定点击顺序。不干预的发展事先确定动机与节点，避免临时为了反转而惩罚玩家。新后果可以引出新事务，旧事务仍必须先收束。

节奏由日常、准备、紧张执行和事后回响构成。场景没有有意义变化时可结束或自然跳时，禁止每回合相同规模长文、重复背景、固定三选一及永久悬念。

## 9. 地图、旅行与通信

保留地点与地形资源、政治缩放和道路。地图默认显示当前位置、人物最后已知位置、相关事务、可行目的地、耗时与明确费用。三维渲染失败不改变世界规则。

出行合同：目的地、路线各段交通方式、真实成员、载具或购票依据、携带重要物、费用与已知风险。支持在港口等合法节点换乘。地图按钮和文字输入提交相同合同；角色没马，任何入口都不能默认骑马。

平静路段直接推进；封路、盘查、补给、消息和期限到达等只有需要选择时才停止。按既有决定可以自动继续的通知只记录，不制造不必要的暂停。相关天气、政治封锁与已知道路情报进入路线规则，尚未具备结果规则的风险不显示精确概率。

途中使用路段 ID 与段内进度作为权威位置。返回、改道、物资可达性都从该位置计算，禁止地图画在半路而规则当作仍在上一个城市。地点、房间和路段分开，抵达城市不等于进入任意房间。

费用按服务阶段列明：订金、路段服务费、消耗、退订条件。改道重新计算未发生的费用，不重复收全程费用；余额不足整组出发操作不成立。

消息有发送者、收件人、渠道、发送位置、预计路径和送达条件。送出、送达、阅读、相信分别是事实；收件人移动后根据渠道转送或送达旧址，不实时跟踪。封锁可影响信使，渡鸦需要相应设施。期限不能由模型直接填零天绕过距离。

世界真相与各人获知快照分开。地理常识可以公开，实时驻军、人物位置和私人库存不是自动公开；保留来源、观察时间和不确定性。未获知的世界变化不能通过地图覆盖或资产计数泄露。

## 10. 人与仓储、装备、经济和身体

### 10.1 仓储前台

玩家默认只看随身、存放、交给他人三类。常服、出行与战斗装束按套操作；常规衣物整理、同类小物合并和获准的装卸自动完成。检索、只读盘点不消耗世界时间；真正的搜查与人工盘货可以耗时。

前台容量采用轻装、普通、重装、需载具的直观说明，后台保留统一容量单位。只有物品体积实际影响选择时才提示取舍，不逐格整理零碎生活用品。重装应影响相关潜行、攀爬或旅行，否则不收取管理负担。

### 10.2 权限与交接

重要物件追踪稳定 ID、位置、法理所有者、实际保管与状态。容器移动后内容沿包含关系派生位置，同件物品不能复制、循环包含或同时被两个人装备。

进入、查看、取出、借用、转交、出售是不同授权；可以存在有范围与有效期的常设许可。同地图地点不等于同场、可接触或有权取用。

托管、借还和赠予引用当事人的实际接受或职责依据；一次自然交谈即可成立，不另做繁琐审批小游戏。借出不转移产权，继承产权不传送物品，远方调拨建立真实运输。未装备的存放物不提供人物效果。

普通取用已授权且无争议时直接完成；锁闭、拒绝、物品缺失、空间不足、时间紧迫时才进入场景。自己远方仓库显示最后核对库存，报告来源与实际库存分离。

### 10.3 金钱与组织资源

保留有单位的实际金额，用统一最小货币单位结算，金币银币按固定内容规则显示与换算。不给性格附加泛化收入倍率。退款、转账、借款与收入分别标记。

个人钱包和组织预算分开；统治者不能默认把全部国库当个人零用。日常费用按已同意的停留或服务时段汇总，无需每顿付款。重要交易、雇佣、旅行、治疗和赔偿明确显示金额、对象与交割条件。

### 10.4 装备与身体

保留实质装备差异：护甲防护、武器适用范围、工具资格、场合认可的服饰、著名物件的身份作用。删除重复品质评分和默认百分比维护，使用完好、受损、不可用；伤害或重要事件触发损坏，不每挡一下固定掉耐久。

伤口按原因、部位、严重度、稳定状态和恢复条件保存；身体显示从伤口汇总，轻伤不覆盖旧重伤。严重腿伤影响移动，手臂伤影响相关执行，效果单一来源不重复扣分。治疗要绑定目标、可访问材料、时间和能力；休息在治疗条件满足后促进恢复，不直接免费满状态。

补给、寒冷、疲劳只在旅途、逃亡、围困等相关处境激活；安全日常生活自动处理。修理、治疗、装卸和休息统一使用世界时间，避免付了耗时却不影响期限。

## 11. 冲突、政治与身份尺度

个人冲突记录目标、双方、位置、态势、身体、可用物和退出条件。一次 D20 解决一个重要交锋，不为每次招架独立掷骰。逼退、缴械、掩护、拖延、突围与击杀有不同前提与结果；护甲与姿态改变失败后果和可用方法。

局部战役使用目标、指挥者、实际兵力、供应、路线、情报与态势。前线指挥用军事，后勤安排用管理；一次军事骰不能直接改王国归属。占领、停战、正式授封分别引用已经成立的事件。

权利区分法理、实际控制和受权范围。岗位、领地与名声改变可用行动，不简单变成所有检定的通用加值。领主主要决定人选、预算和立场；普通库房与装备事务由受权人物处理。

死亡可以发生，但必须来自具有实际致命风险的处境，不能因为寒暄自然 1 就处决。被俘、退却、失物和失败后继续生活都可成为有后果的结果，不保证自动救援。死后保留遗体、随身物、远方财产和未决义务的真实去向。首版不自动切换继承人；允许封存人生、另开分支或另开人物。

## 12. 成长与原作

原始 CK3 点数可通过有来源的实践与训练小幅成长。每个领域以已验证经历、指导和投入形成里程碑，达成后获得 +1 等明确提升；相同安全动作不能无限刷。成长速率在长局验证，不能让几周经历把常人提升到原作顶尖。

专长、教育、职位和社会身份提供资格或有条件效果，与点数有不同作用。关系和资源成长应更频繁打开新方法。伤势与失败可以改变发展路线，但不强迫玩家人格转变。

原作是开局事实与条件性事件模板。每个重要节点检查真正相关的存亡、位置、动机和依赖；只因相关条件改变才偏离。有策划替代路径则启用，否则明确关闭该事件，不虚构已实现的全世界替代历史生成器。

魔法与巨龙仅支持有定义的身份、资格、位置、意愿与代价。特质名称不等于可任意传送、预知事实或无限使用特殊能力。

人生可以在自选目标完成、退休、离开或死亡时结束，回顾依据重要选择及其实际后果；允许继续日常，完成事务不强制马上派发新危机。

## 13. UI 与反馈

默认主界面以正文、当前场景、行动输入和可展开的当前事务为中心。常用入口为人物、行装、地图、日志；设置与存档放菜单。不同时常驻全量属性、仓库、世界新闻和任务队列。

筹划界面只在用户安排多人或多步骤行动时展开：目标、步骤、人员、时间占用、费用与已知风险。小动作一键验证，大动作先预填意图；建议选项不意外提交。

检定显示骰面、使用的主辅属性、明确修正、结果和实际后果。对隐藏难度保留信息边界，不通过“查看公式”泄密。拒绝时解释可观察阻碍及符合现场的替代方法，不伪造不存在的唯一通路。

输入失败可恢复，取消不扣款；查看人物返回后保留草稿和阅读位置。主界面区分待执行、已确定结果、正在生成文本与已保存，不能把未提交小说当世界事实。

## 14. 运行时架构

### 14.1 四层责任

| 层 | 内容 | 写入权 |
| --- | --- | --- |
| 内容层 | 人物和地点基线、方法定义、物品功能、事务骨架、原作节点 | 开发期内容编译，不写当前周目 |
| 规则层 | 资格、主辅属性、D20、费用、位置、时间、权限和结果 | 生成经过验证的事务计划 |
| 世界状态层 | 当前人物、物件、场景、事务、认知、事件与存档分支 | 单一提交服务拥有权威写入口 |
| 表达层 | 对白与正文、地图、人物卷宗、行动和结果视图 | 只读可见投影，提交意图而不直接改世界 |

### 14.2 最小领域对象

| 对象 | 必需内容 |
| --- | --- |
| Character | ID、CK3 属性、特质、身体、身份、位置引用、职责 |
| Relationship | 双方、方向性态度、重要共同经历、证据引用 |
| Scene | 地点或旅途锚点、实际在场者、当前焦点、可接触范围 |
| Undertaking | 目标、参与者、阶段、成本、期限、发展与结束条件 |
| ActionAttempt | 请求与分支 ID、方法、事实版本、属性快照、随机样本、结果范围、确定结果 |
| Asset / Container | 唯一实例、位置父节点、容量、产权、保管、使用状态 |
| Authorization / Obligation | 主体、范围、成立依据、期限与履行状态 |
| Journey / Assignment | 路段进度、真实成员、载具、资源占用、阶段结果 |
| Knowledge / Message | 声称的事实、观察快照、来源、受众、传递与送达条件 |
| Event / WorldClock | 已提交变化、时间、因果与知情传播 |

这些是逻辑职责，不要求每个对象都创建一套面板或独立服务。物理位置单一父节点，关系不自动共享背包与秘密。所有 UI 数据都是指定分支、修订号、观察者下的投影。

### 14.3 统一执行管线

1. 捕获玩家意图、待执行 UI 操作、requestId、branchId 和世界修订号。
2. 编译有限的可见上下文；必要的隐藏事实由规则域处理，不塞进普通叙事提示词。
3. 模型解析方法与目标；规则把它编译成行动合同，检查资格、参与、时间和依赖。
4. 若有超出原意的新重大代价，保存提案并停在确认节点；普通既定行动无需额外确认。
5. 创建持久的待提交 ActionAttempt，采样并锁定骰面和结果。该记录不是已发生的世界事件。
6. 在隔离事务视图结算人物、物品、钱财、时间与到期事件。出行与日期只能由同一计划器推进。
7. 将已确定且玩家可知的事实提供给叙事模型；它只表述和生成后续建议，不能新造伤势、付款或承诺。
8. 正文合格后，全部状态、事件、知识与文本按同一版本原子提交，并标记 attempt 已提交。
9. 更新所有可见投影。失败或取消保留原世界与草稿；同一 attempt 恢复时复用骰面。撤回后旧分支异步任务不能写入新分支。

规则结果合法但模型持续不可用时，允许玩家明确选择以简短事实记录完成同一结果，不另抽结果或增加后果。正常回合默认解析和叙事两次调用，普通确定性操作零调用。所有后台议程不逐人调用模型。

### 14.4 时间与失败边界

采用一个规范游戏时钟，基于项目统一日历加日内分钟表示；季节是独立世界状态，不按中文字符串猜测，也不把月份强制等同长夏长冬。按时间顺序处理事件，同时间使用固定阶段：完成已成立的移动与交付 → 传播对应知识 → 检查义务 → 触发后续议程。因果依赖优先于无关事件排序。

单个行动的必需步骤失败整组不提交。多个独立行动可以各自成立，但任何后一步依赖前一步时要显式绑定，不能买药失败却继续扣耗材治疗。多阶段事务只回滚尚未提交阶段，不回滚已经完成的人生经历。

### 14.5 上下文与持续性

精确事实、重要义务与当前状态必须来自事件和结构化存档，不能以模型摘要取代。旧对白可压缩，摘要不能扩大受众或把传闻升级为真相。当前场景、直接相关人物、当前事务和可知事件优先加载，控制人物与正文预算；增加全世界人物数量不应线性扩大每回合提示词。

## 15. 现有系统处置与实施顺序

| 当前系统 | 裁决 |
| --- | --- |
| CK3 属性、特质与人物 ID | 保留原值与身份，重做消费者和重复加成 |
| D20 与结果展示 | 保留骰子，重做主辅属性、难度依据、结果带和重试合同 |
| 世界基线、账本、存档位 | 保留并适配，不建立第二套权威世界 |
| 主辅属性之外的任意模型改点 | 收紧为有来源成长 |
| 关系和承诺 | 保留记录，绑定真实人物回应及后果 |
| 地图、路线与视觉资产 | 保留，统一出行入口、时钟、位置与认知 |
| 仓储、保管与产权 | 后台保留必要事实，前台合并和自动化 |
| 百分比耐久、冗余品质和逐件整理 | 撤出默认规则，映射到用途与状态 |
| 独立政治和人物直接结果命令 | 只接受已验证事件产生的结果 |
| 新旧旅行结算并存 | 统一到单一计划器，不以兼容分支隐藏规则差异 |
| 未兑现的风险、经济与继承功能 | 关闭误导入口，达到完整交付条件后再开放 |
| 大量导入美术和模组资料 | 保留资料价值，不据此承诺对应模拟机制 |

实施依赖：

1. 固定新行动合同、主辅属性和 D20 数值基线，先用纯规则样例验证。
2. 统一提交、时间、旅行、资产交接与观察者投影，解决既有路径差异。
3. 接入场景、人物回应、准备和单一事务流程，制作一段可完整收束的内容。
4. 简化行装与仓储，接入真实伙伴委派、通信和相关地图选择。
5. 增加身份尺度与原作重点事务，完成不同开局与长局验证后再扩展内容。

新玩法使用明确的新规则版本；原型另开存档，禁止热切换现有周目。迁移保留旧数据副本，CK3 点数原样保留；旧确定事实尽量继承，旧文本不自动推导隐秘动机、许可和承诺。未完成迁移时不把旧档强行放进新规则，不删除用户存档或大量资源来表示“重做完成”。

## 16. 贯穿示例与验收

### 16.1 一段可玩的事务

玩家的朋友将在三日后被转移。已知地点、看守制度与部分关系，但尚不知道侧门换班安排。玩家有一笔有限资金、两个愿意讨论合作的人，以及自己的 CK3 属性。

- 可以合法求情、出资赎回、伪造命令或计划潜入；不同方法使用不同主辅属性与前提。
- 可以花半天查换班、花钱取得工具、让熟人担保，或直接行动。调查打开方法，担保降低交涉阻力，接应降低撤退失败后果；它们不是同一种加值。
- 不能把所有准备做完仍停在原时间。派去调查的伙伴无法同时在现场接应。
- 潜入使用谋略及适用辅属性，文书步骤由有资格的人处理。每个骰面先锁定结果，正文只表现该结果。
- 骗开门成功而带人离开受阻，先前开门事实仍成立。玩家可谈条件、撤退或承担新的战斗风险。
- 成功后人物和物件实际移动；失败可以丢钱、暴露或错过转移前机会，不强行免费挽救。
- 朋友获救后允许一段自然相处。救援记忆影响以后，但不会使他从此无条件服从。
- 事务有结算和结束；玩家可以休息、接受新的生活目标，或继续处理自己的事情。

### 16.2 必需验证

1. 同一出行经地图和文字得到相同的资格、费用、成员与时间结果。
2. 21、22、23、24 等属性全部进入定点计算；对全部 20 个骰面枚举概率，不能用显示上的小数虚称连续胜率。
3. 高属性和有效准备不降低成功率；协助与特质不重复计价，同样事实换措辞不重骰。
4. 一件事务至少三种有实质不同成本或条件的方法可完成；允许拒绝与退出，避免唯一关键词解法。
5. 成败与接近成功分别实际游玩，失败不抹掉先前成功，也不强制代付新重大代价。
6. 仓储取物、借还、赠予和运输不复制、不瞬移；常规授权取物与换装无需逐件整理。
7. 途中位置、队伍、物资、费用、期限、消息和地图一致；明确覆盖半路返回、同日交付与约定到期。
8. 未知死讯、秘密交接和远方库存不通过地图、卷宗、日志或公式详情泄露。
9. 取消、断网、正文失败、重复请求、刷新、撤回与新分支不扣两次资源、不重骰、不串档。
10. 普通人物与有权人物各完成一段事务；后者通过授权调动资源，不被迫逐件管理全部库房。
11. 至少一段安静日常无需危机和数值奖励也能自然结束；模型不代写玩家意愿与承诺。
12. 对至少一条周目进行 100 回合连续验证，检查关键记忆、未了事项、费用、概率平衡与上下文增长。

本提案仅完成设计整理，未执行以上新玩法验证。发布判断需列出实际样本和失败案例，构建成功不能证明玩法、叙事质量或数值平衡已经通过。

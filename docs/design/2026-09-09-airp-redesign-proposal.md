# 冰与火之歌 AIRP：完整玩法与机制修改方案

版本：2026-09-09 · 讨论收敛稿

定位：方案文档，不代表已实现，也不代表已验证平衡性。依据本次讨论整理，未逐项审计当前代码；下文“删除、保留、重做”均为目标设计决策，落地前须核对现有实现与存档。

## 一、最终方向

玩家扮演冰与火之歌世界中的一个人，主要通过自然语言说话、行动、试探、准备和作出承诺。世界按照稳定规则回应，人物拥有自己的意愿，选择留下持续后果。

UI 是角色的感官、记忆与状态展示，不是主要操作菜单。游戏性来自方法组合、有限资源、信息差、时间压力、相互冲突的利益以及必须承担的后果，而非提示词长度、按钮数量或 AI 文笔。

不将游戏固定为宫廷权谋、领主管理、任务刷取或自由聊天。骑士、旅人、学士、密探、商人、无地贵族都应有成立的玩法；闲聊、恋爱、陪伴和日常生活也是有效游玩，不要求每段互动都有收益。

### 最终交互原则

1. 普通自然语言就是完整输入，不要求玩家学习指令格式或特定关键词。
2. 同样意图、条件和风险，短句与长提示词使用同一套规则。
3. 玩家可以提出菜单外的方法；系统根据条件组合裁定，不强行套入少数固定路线。
4. 玩家说“我做了什么”是行动声明，不是结果写入权。不能靠“他已经同意了”修改 NPC 意愿。
5. AI 不代替玩家决定台词、动机、承诺和重大后续行动。
6. 系统在下一个有意义的决定处停下，不一次替玩家演完整段冒险。
7. 未知信息不是随意编造的许可；UI 不展示角色无从得知的事实。

## 二、保留、删除与重做

| 对象 | 修改方向 |
| --- | --- |
| 世界观、已有地理和人物数据 | 保留可用资产；统一开局年代，核对事实冲突及数据来源 |
| CK3 六属性原始点数 | 保留外交、军事、管理、谋略、学识、勇武；与专长和行动裁定分工 |
| D20 | 保留为关键不确定行动的裁定工具，不用于每句话和每次普通移动 |
| 2000+ 人物 | 保留存在与连续性，采用分层模拟、按需展开，不全员逐轮调用 AI |
| 2000+ 地块 | 保留空间与通行骨架，不要求逐格操作，也不要求每格有任务 |
| 单一好感条解锁行为 | 从核心交互中移除；以方向性关系、经历、意愿和条件替代 |
| 重复送礼、聊天刷点 | 移除无上限收益；重复行为需有新的意义才能产生成长 |
| 通用动作按钮墙 | 移除；不常驻“讨好、威胁、邀请、说服”等菜单 |
| 强制提议表单、路线配置器 | 不作为主要入口；相关结构由输入解释器在后台识别 |
| 逐格旅行、重复日常弹窗 | 改为意图驱动的旅程推进，在值得决定的节点展开 |
| 仓储搬运与资源生产微操 | 降级；仅保留影响角色行动、财产归属和承诺的部分 |
| 大量同质装备和被动加点 | 合并或删除；装备和专长必须改变可行方法、成本或后果 |
| 任务板与线性剧情锁 | 改为人物处境和开放事务；允许拒绝、协商、放弃与另辟路径 |

这是目标架构，不是对未审计的现有实现作事实判断。删除机制不等于立即删除文件或抹除旧存档。

## 三、核心游玩循环

观察处境 → 自由表达意图 → 运用能力、工具与关系 → 世界和人物回应 → 确认结果与代价 → 形成新处境。

系统必须同时支持三种节奏：

- 日常扮演：聊天、陪伴、吃饭、叙旧；默认直接回应，不制造无意义检定。
- 行动场景：调查、交涉、潜入、决斗、救援；出现有限机会、风险和对手反应。
- 世界推进：旅行、休养、等待、长期学习；压缩平淡时段，在新的重要条件出现时停下。

没有固定“一条消息等于一天”。用实际行动决定时间消耗；说一句话、翻墙和赶路不能采用相同时间单位。

### 一次自由输入如何处理

示例：“我递上介绍信，不提罗温。如果守卫追问，就先试探他是否认识我的叔父。”

后台依次识别：

1. 已提出的行动：递信、隐瞒同行者。
2. 对外表达：玩家明确说出口的内容；内心计划不自动被 NPC 获知。
3. 条件后续：守卫追问才可能触发试探；如果情况显著改变，应把决定交回玩家。
4. 所需条件：信在手、守卫在场、双方能交流。
5. 裁定方式：直接成立、明确不成立，或需要关键检定。
6. NPC 回应与世界事件：先通过规则校验，再落入存档。

同一句话中若存在多步计划，执行到条件改变或重大决策点为止。轻微措辞含糊可采用合理解释；涉及杀伤、重大支出、公开担保、不可逆承诺或歧义目标时应先确认。玩家已明确授权的风险，不重复询问。

## 四、属性与 D20

### 六属性分工

| 属性 | 主要影响 |
| --- | --- |
| 外交 | 交涉表达、协调冲突、争取支持 |
| 军事 | 战术判断、队伍组织、战场指挥 |
| 管理 | 物资安排、账目、经营判断与执行组织 |
| 谋略 | 隐瞒、欺骗、识破布置、隐蔽行动 |
| 学识 | 文书、历史、医学、知识推理 |
| 勇武 | 个人战斗、攀爬、力量与身体执行 |

按具体方法选择属性，不按场景名称固定。例如“说服守卫”可主要依赖外交，“指出军令漏洞”可能依赖学识，“伪装成军官”则可能依赖谋略。

### 组合与中间点数

主辅属性制作为第一版默认方案，不强制每次使用两个属性：

- 主属性承担核心执行；辅属性必须能解释其因果作用。
- 两属性有效值暂定为：主属性 × 70% + 辅属性 × 30%。
- 单属性动作直接采用该属性；复杂计划拆成有意义的阶段，不把六项全部相加。
- 初始试验公式：D20 + 有效属性 ÷ 5 + 情境修正，对照难度。
- 原始点数不先取整，因此每一点都有贡献；也不能承诺每一点都立刻增加 5% 成功率，D20 的结果分界是离散的。
- UI 默认展示简短适用原因；精确计算可展开查看。计算使用定点数避免边界浮点误差。

以上系数和阈值均为待测初值。高属性可能使普通任务自动成功，这是能力的价值；不要为了保持失败率而偷偷提高难度。真正不可能的事情不能通过掷出 20 强行成立。

### 裁定约束

- 没有风险、不确定性或有意义后果时不掷骰。
- 关系和身份可能决定是否允许尝试，不能被高骰面直接绕过。
- 准备可降低阻力、打开方法或消除一次检定，不一定都变成 +2。
- 结果分为优势成功、成功、部分成果或条件机会、失败；后果必须匹配动作性质。物理动作不适合凭空追加“对方提出条件”。
- 第一版可试验：超过难度 5 为优势成功，达到难度为成功，差距 3 以内进入部分结果，其余失败；再通过场景测试调整。
- 自然 1/20 暂不设通用自动失败/成功；若未来加入，需按玩法单独验证。
- 条件不变时不能换一种说法反复掷骰。重新尝试需要新信息、新准备、新代价或实质不同的方法。
- 关键骰面与结果持久记录，叙事重试不得重抽。读档策略与难度模式分开设计，不靠隐蔽惩罚阻止正常存档。

## 五、Build：构筑做事方法，而非堆数字

Build 由能力基础、技艺专长、处世原则、经历专长、装备工具、关系配合共同组成。不设不可跨越的职业墙，但训练时间、互斥做法、携带限制和关系维护使全能有成本。

### 专长必须满足的条件

至少改变一项：可行动作、执行顺序、资源转化、准备收益、失败后果。纯数值专长可少量存在，但不能构成大部分成长内容。

示例：

- 留有余地：交涉接近成功时，有机会接受附加条件继续推进；不能迫使对方越过底线。
- 预留退路：事先准备撤离路线后，某些潜入失败可转为弃物逃离；失去目标仍是失败。
- 决斗反击：主动承受对方压制，争取反击窗口；对方可识破或改变节奏。
- 公开立誓：允许把未来名誉作为担保；违约带来明确、可传播的后果。

专长根据玩家行动自动判断是否适用，不要求输入名称。触发时用一句可展开说明反馈，不能当作玩家看不见的隐性加成。

### 成长

训练提供基础提升，关键经历开启新方向，玩家作出成长选择。经历条件必须可追溯，不以 AI 临时觉得“很精彩”作为唯一门槛。

重复低风险聊天、送礼、翻同一堵墙不能无限刷成长。处世原则由玩家选择或确认；系统不能因为一句台词就永久判定玩家性格，更不能替玩家强制发言。

### 平衡目标

同一问题至少支持数条真实不同的解法，并允许混搭。差异体现在前置条件、准备过程、资源损耗、暴露程度和后续关系，而不仅是换一项属性掷骰。独行路线与合作路线都必须可行。

## 六、人物、关系与 2000+ NPC

### 关系不是一个购买行为的数值

后台可以记录信任、情感、畏惧、义务和利益等方向性信息，但不能合成唯一好感分。你信任他不等于他信任你；喜欢你不等于愿意替你冒生命危险。

NPC 决策结合自身目标、职责、底线、当前条件和已知信息。底线通常不向玩家直接公开，但拒绝须提供能合理观察到的反馈，避免所有互动变成猜隐藏答案。

### 提议与反提议

玩家直接输入请求。系统后台提取请求内容、玩家承担的代价、说服依据和允许的余地；不要求填写表单。

NPC 可以接受、拒绝、追问或修改条件。例如：“我可以接应，但不进城。我得照顾弟弟。”玩家继续自由协商，而不是不断按说服按钮。

同样重要的是没有交易目的的相处。恋爱、亲情、友谊、争吵和告别不必成为收益工具。

### 关系配合

共同经历可解锁双方特有的合作方式，例如掩护默契、彼此兜底、公开担保。需要对方在适当位置、知道计划、具备能力且愿意参与。NPC 不是可随时插拔的装备。

### 分层运行

| 运行层 | 更新方式 | 初始预算参考 |
| --- | --- | --- |
| 同场人物 | 当前意图、观察、对话与行动；并非每人每轮都必须发言 | 约 2—8 个主要互动者 |
| 牵挂人物 | 按承诺、目标、关系变化与重要事件推进 | 约 10—30 人，非社交硬上限 |
| 远方人物 | 日程、职责、关键世界事件与按需补算 | 其余人物 |

分层是计算精度，不是身份等级。普通侍从可以成为主角生活的核心；国王可以一直只是远方人物。远方人物不能冻结，但也不需要每日生成内心独白。

大型宴会或军营采用主要发言者与群体反应，不同时生成数百段对话。补算必须受已发生的战争、旅行和亲属事件约束，不能在再次登场时重新随机一生。

## 七、地图与旅行

### 三层空间

1. 世界层：目的地、路线、势力边界和大范围行程。
2. 地区层：村落、渡口、小径、营地，以及人物和线索的活动范围。
3. 地点层：城门、大厅、厨房、牢房等有行动意义的空间。

已有地块承载距离、地形、道路、控制权与通行条件。普通地块不必都有任务；重要地点按需展开。无需玩家逐格点击。

### 自然语言旅行

输入“沿河去渡口，尽量避开官道”后，系统依据已知路线、角色能力与限制确定可执行方案。没有掌握的小径不会凭空出现；角色可以询问、调查或冒险寻找。

点击地图只查看信息，不自动移动。路线选择存在重大差异而意图不足以决定时，给出简短说明并让玩家选择；无实质差异时可自行完成常规路径安排。

### 路线参与 Build

- 官道：速度和补给有优势，但可能被盘查、留下记录。
- 商队：获得掩护与互助，但受行程和约定限制。
- 山径：依赖野外能力、工具或向导，承受时间与体力成本。
- 人际通路：担保、渡船、藏身处与引路，附带他人的风险和条件。

这些不是固定四选一；它们是可组合的规则条件。同一个地方，不同构筑应产生不同进入方式与抵达后处境。

### 旅途节奏与地图认知

普通行程压缩记录；桥毁、盘查、约定即将错过等实质变化才展开。事件来自当地状态与前因，不按步数机械刷强盗。

稳定地理与动态情报分开。人物位置显示最后获知时间与来源；道路封锁可能是旧消息；玩家离开后不再获得实时人物雷达。

## 八、物品、仓储、经济与大规模事务

每件重要物品区分所有者、保管者和所在位置。属于玩家但借给他人的剑，不能同时装备；存放在异地的工具不能在当前行动中使用。

保留随身、同伴携带、坐骑或运输、固定寄存四类位置。负担、易损、隐蔽性与取用条件影响行动，但不要求逐件搬运常规杂物。允许“把备用衣物寄存在旅店”这类批量自然语言操作。

资金、补给、欠款、报酬和礼物服务于角色生活与选择，不先扩展复杂商品经济。重复礼物没有稳定兑换忠诚的公式。

领地、军队、商队与家族通过玩家实际身份开放交互：请求、命令、安排和承担责任。没有任职或授权不能直接操控。大战可以作为世界事件或局部行动背景；完整战略经营不是首个原型的必要依赖。

## 九、UI 修改方案

### 总体布局

- 中央：当前场景、对话、事件反馈和唯一主要输入框。
- 左侧：常驻“我的角色”紧凑侧栏。
- 右侧：按需展开的人物、地点或物品信息，不强制长期占屏。
- 窄屏：左右栏收为入口，优先保证叙事与输入空间。

### 左侧：自己

常驻展示名字与身份、当前有效状态、核心专长摘要、随身重要物品与资金、近期关键承诺。六属性可紧凑折叠；完整传记、家谱和仓储在展开页。

信息应解释作用，例如“左臂伤势：攀爬受影响”“家传长剑：由罗温保管”。点击用于查看，不默认执行换装或发动能力。

### 右侧：人物

顺序为当下可见状态、你们的关系经历、未了之事、已知线索与来源。身份、亲属和能力印象放次级区。

不展示读心式动机、精确忠诚值或未获知秘密。不常驻通用行动按钮。索回物品、发出邀请、追问隐情均由玩家输入。

### 地图和物品面板

地图展示已知地理、目的地、路线信息与情报时效；物品展示位置、归属、保管与实际用途。查看不推进时间，实际行动才推进时间。

### 保留的少数常用功能

发送／停止生成、存读档、回看记录、打开角色或地图、查找已获知信息、关注重要人物。可选“插入人物名”只帮助准确引用，不替玩家完成行为。

停止生成只停止输出，不得留下半次世界写入。一次动作采用完整事件提交，重试可以恢复已确定的结果而非重复扣款或掷骰。

## 十、人物信息怎么填写

采用三层分离：世界事实 → 某角色获知的记录 → UI 可展示内容。

| 信息 | 来源及更新方式 | 展示原则 |
| --- | --- | --- |
| 姓名、年龄、亲缘、头衔 | 经审校的设定库或一次性原创生成；保留年代与来源 | 不同角色的知情范围不同 |
| 六属性、核心性格、专长 | 设计标定及职业范围校验，成长事件更新 | 玩家看自己的精确值；NPC 默认看有证据的印象 |
| 位置、伤势、财产、存亡 | 游戏事件更新，保存时间和事件 ID | 当前事实不等于玩家实时知道 |
| NPC 目标、底线、秘密 | 角色内部状态，受事件与经历改变 | 不直接进入玩家面板 |
| 关系与承诺 | 双方事件、实际表达及行为记录 | 有方向、有条件、可追溯 |
| 传闻与自述 | 发言者、传播路径、获知时间 | 标注来源；不能直接当成客观事实 |
| 外观与对话风格 | 既定信息优先，无冲突空白可按需补充 | 补充后存档，不能每次重抽 |

原著事实不足时留空或标记未设定，不能把推测包装为原著。游戏开始后形成的架空历史与开局设定分开记录，不再强制回归原著剧情。

对 2000+ 人物先填最小底档和必要关联；登场时展开外观、表达与当前处境；深交后主要依靠游玩事件积累细节。不能预填并未发生的共同回忆。

## 十一、底层实现边界

### AI 负责

理解输入、提出结构化行动候选、在角色知情范围内演出对话、总结可追溯记忆、描述已经确定的结果。

### 规则系统负责

权限与前置条件、时间和位置、物品与资金、属性计算、骰子、状态变化、事件提交、存档一致性与可见性投影。

NPC 的回应可由 AI 提议，但必须遵守其事实、知情范围、能力和重要约束；不能为了剧情方便临时创造资源和权限。

### 最小模块划分

1. 输入解释器：区分发言、行动、条件计划和仅供玩家表达的内心内容。
2. 场景与权限服务：谁在场、谁能听见、方法是否可行。
3. 行动裁定器：属性、准备、专长、概率和后果。
4. 人物决策服务：目标、意愿、约束与反提议。
5. 世界事件账本：事实变更、时间、位置、物品、承诺与唯一事件 ID。
6. 认知与记忆服务：每个人知道什么，来源是什么。
7. 展示投影：向 UI 和叙事分别提供允许读取的信息。

生成输出不直接修改全局存档。事件先校验、再原子提交；同一行动重试具有幂等性。裁定失败时维持原状态，不靠编剧情掩盖错误。

## 十二、贯通例：救出被扣押的朋友

玩家先通过地点、目击者和人物交谈确认扣押原因。不同构筑可以争取公开审理、寻找证据、协商担保，或准备秘密救援；不预设唯一任务解。

玩家输入：“请罗温在渡口接应。我带绳索去看后墙，不惊动守卫。”

1. 检查罗温是否在场或能收到消息；不能自动远程知情。
2. 罗温依据自身处境提出条件；玩家决定是否接受。
3. 检查绳索位置与取用成本；寄存在房间就先取，不隔空使用。
4. 地图按玩家意图推进到可观察后墙的位置；只提供角色能看见的信息。
5. 玩家观察后决定继续、变更或撤退；观察不自动升级为潜入。
6. 攀爬时使用对应属性、伤势与准备。失败若符合已备退路，可以弃物撤离；不是无损重试。
7. 结果同步更新位置、物品、警戒、目击者信息和相关承诺。
8. 下一段 RP 可能是会合、解释失败、处理追踪或协商另一条出路。

故事性来自双方选择，游戏性来自可理解的条件和取舍；AI 文本负责表达这些变化，而不是替代这些变化。

## 十三、实施顺序

### 阶段 0：盘点与迁移设计

逐项核对现有模块、存档字段、人物与地图资产。建立保留／适配／废弃清单和存档版本策略；保留可回退入口，不立即物理删除旧数据。

### 阶段 1：一座城的闭环

只做一座城、周边路线、约十二个核心人物、三种构筑方向和一场变化中的危机。先接通自然语言输入、事实裁定、NPC 回应、时间推进和最小 UI。

### 阶段 2：选择真的不同

加入反提议、关系配合、工具与准备、通行条件、失败延续和一次有意义的成长抉择。测试骑士、密探与说客等路线能否混搭，日常 RP 是否自然。

### 阶段 3：扩大连续性

加入远方人物调度、来信与消息传播、地区旅行、寄存与借用、批量人物底档和认知投影；先验证性能与一致性再扩展至全量地图和人物。

### 阶段 4：专项拓展

根据实测选择深化战斗、学术、商业、家族或领地玩法。不要在基础循环未成立时同时铺开所有系统。

## 十四、验收标准

### 游戏性与可玩性

- 同一核心处境至少存在三条能完成的路线，且成本、过程和后果明显不同。
- 更换构筑影响可用方法、行动顺序或失败处理，不只是成功率。
- 准备和调查至少能改变一项前置条件或明确风险，不只是获得一段文本。
- 拒绝 NPC、任务失败或错过约定后仍有新的可玩处境，不一律死路或原样重试。
- 独行与合作都有可行路径；没有唯一必须讨好的 NPC。
- 同一句意思用简短表达和长提示词表达，得到相同规则待遇。

### 角色扮演

- 私人想法不泄露给 NPC；玩家没有说出口的话不被伪装成台词。
- NPC 可以反提议与拒绝，且回应能由处境解释。
- 闲聊和陪伴不会被强制变成检定或任务。
- 角色记得已发生的重要经历，不凭空添加共同历史。

### 系统一致性

- 离场人物不再显示实时位置；传闻带来源与时间。
- 物品不能同时存在于两个保管位置；重复请求不重复结算。
- 未获知秘密不进入 UI 或玩家侧叙事上下文。
- 条件不变不能靠改写提示词重掷；合法新方案可以重新裁定。
- 世界大事影响相关远方人物，不全员逐轮生成文本。

### 验证方式

先用固定场景回归测试检查规则，再用真实试玩检查理解成本、自由度、重复游玩意愿和等待时间。测试前定义运行设备、模型与延迟预算，不在本方案中虚构性能承诺。

本方案的创新点是自然语言下的方法组合、可协商的合作、关系改变空间通行，以及可追溯的持续后果。它们是待验证的设计假设，不是“系统越多越好玩”的保证。

## 十五、最终边界

第一版要证明的是：玩家不用菜单也能清楚行动，不靠长提示词也能发挥构筑，不靠 AI 临时编造也能产生有变化的故事。

左边帮助玩家记住自己，中央让玩家亲自扮演，右边帮助玩家理解世界。地图、人物、仓储、属性和骰子都服务于这一件事，而不是各自成为独立的管理作业。

# 据点、仓库与装备：专项审视和替换方案

本轮结论：需要共同重做。当前最大问题是物理位置、保管权限、领土统治和装备状态互相混用；界面和世界规则还对同一件事给出相反判断。只简化物品卡片不能解决。

本文补充并细化总方案，保留角色扮演优先的方向。核心保管、容量、装备去向和治疗合同已接入；暂缓项与验证边界见 [实施状态](../IMPLEMENTATION_STATUS.md)。

## 1. 已确认的问题

## 2. 产品决定：取消泛化“据点”，保留有用途的落脚处

游戏里的家、客房、营地、藏身处、商会仓库和统治者城堡可以继续存在，但不共享一套“建个据点就得到大仓库”的通用玩法。

| 概念 | 定义 | 必须有的形成方式 |
|---|---|---|
| 落脚处 | 角色暂时或长期停留生活的地方 | 自有、受邀、租住、借宿、扎营或实际占据 |
| 储藏处 | 某个具体空间/器具，用于放东西 | 已存在的衣柜/箱子/库房，或实际设置的容器；可以位于落脚处中 |
| 使用权 | 谁可进入、取用什么、持续多久 | 主人许可、租约、岗位职责、钥匙配合合法权利、有效委派等 |
| 领地与组织设施 | 为共同事务提供资源的资产 | 头衔或组织权力、掌管者和制度；不能自动等同私人财物 |

普通角色的常用入口称“住处与寄存”，按需出现。统治者才在政务中看到城堡设施、军械和公库。游历者没有固定住所也能完整游玩，不被迫先拥有基地。

落脚处的角色扮演价值来自安全休息、私下会面、消息递送、主人关系和存放重要物件。只实现当前内容用得到的能力，不新增房屋升级树、离线产出、繁复建造计时或仓库等级。

建立方式拆开：已有客房的租住是合同；放下行囊形成临时存放状态；扎营需要当前条件与物资；新建永久建筑是另一个长期工程。模型不能用同一种 create_site 输出把四者都变成即时储存容量。

## 3. 仓库替换为具体保管与交接

每件重要物品保持唯一实例。分别记录所有权、当前占有/保管、物理位置与允许的操作；寄存不会自动转移所有权，盗取成功改变占有也不等于变成合法赠与。

**本地直接存取**：人在实际可接近的储藏处，具有取用依据或明确采用非法手段；校验数量、接收空间与场景条件后一次提交。进入同一座城只提供“去取”的机会。

**请人送来**：记录委托对象、被取物品、交接地点、报酬/授权、途中耗时和异常。东西在送达前仍在原保管处或运输途中，不能穿戴；已经被预留的同一件物品不可再许给另一个任务。

**远方寄存**：展示最近一次可信清单和消息日期，不暴露实时仓库变化。可以通信、询问或提出运送请求；不能远程点一下转入随身。只在剧情相关时模拟延误、损坏与失窃，不给每次寄存随机惩罚。

**非法取物**：玩家可以尝试撬锁、骗取、偷窃或强抢，系统先判定接近机会与冲突，再提交结果；谁知道发生了什么由观察和消息决定。没有许可不会把自由表达彻底封死，但不会作为正常无成本转移执行。

解除租住、撤营、被逐、仓库易主、角色被俘时，保管状态有明确去向。物品不随面板关闭或地点失去而被删除。营地撤收时应整理为行李、托管、交给伙伴或留下；无人撤收则营地仍留在原地。

容量保持有物理意义的约束，但默认用“可轻便带走/需要打包/需要驮运/装不下”表达，不要求玩家计算每个 0.25 单位。详细装载只在出行与大量货物时展开。当前容量数字不能直接宣布已经平衡，新数值必须通过代表物资组合校准。

## 4. 装备改为装束、取用与负担

默认呈现三组：**当前装束、随身可取、行李与寄存**。装备详情仍保留有实际意义的头身覆盖、衣物层次与手部冲突，但玩家不必填满所有格子才能完成正常生活。

关键区别：

- 剑在鞘中属于随身武器，拔剑后才占用手部；拥有双手剑不意味着吃饭、写信时永远失去副手。
- 穿着的护甲提供符合覆盖/攻击条件的防护；放在行李中的甲不防身，穿着也不会消除其负担。
- 藏在衣内的匕首可以可取用，但不自动给所有 NPC 看见；显眼佩剑可能改变接见条件。
- 书信、钥匙、印章和绳索通过行动上下文参与规则，不需要塞入佩饰栏才生效。
- 身体伤势、训练与协助影响使用方式。不能用“勇武够高”替代缺失的手、缺失的工具或完全不适配的尺寸。

主界面不再以“主手/副手/三件佩饰”作为整个人物的默认骨架。佩饰按实际佩戴位置、可见性与用途处理；取消为凑数值而固定三件饰品的通用激励。必要的互斥和重复效果上限仍由规则定义。

“当前装束”允许保存日常、赴宴、出行、御寒与战斗的目标组合。预设只引用现有物品；缺少物件或远方寄存时说明缺项。玩家可以接受当前可完成的版本，不会自动生成替代品。

换装先算一份统一变更计划：要取哪些物件、卸下哪些、旧物放哪里、是否需要协助、需要多久、当前能否进行。默认旧物留在玩家明确选择的随身包或正在使用的储藏处；没有合法可容纳去向时，提供放置、委托保管或取消，不能按对象排列顺序挑仓库。

日常安全场景的普通换衣允许一键完成；战斗中整套换甲不可一键瞬间完成。只查看装备、比较、编辑预设不推进时间；真正改变物理状态按场景成本结算，不强迫每次整理库存都调用大模型写一篇正文。

## 5. 装备效果要能解释具体选择

保留四类有用差异：能做什么、怎样保护、造成什么负担、向别人表达什么身份。来历和纪念意义另有事件，不换算为万能战力。

| 例子 | 合理差异 | 不采用的捷径 |
|---|---|---|
| 锁子甲 | 对特定攻击与覆盖区域提供保护，长途或隐蔽行动受负担影响 | 全类型伤害统一减一个含糊总分 |
| 北境大氅 | 在寒冷环境御寒；湿透后状态改变 | 所有场景都加外交或每回合固定耗热 |
| 家族印章 | 参与有权限/可能伪造的文书与身份验证 | 装到饰品格就永久增加所有社交成功率 |
| 传家剑 | 实际兵器特性、来历、被识别后的社会含义 | 稀有度自动决定数值碾压 |
| 绳索与药具 | 在相应行动中被选择、取用、消耗或返还 | 未穿戴便完全不可参与；点“使用”只删物品 |

防护摘要与结算使用同一个解释器，按伤害情形说明“覆盖什么/不保证什么”，不再独立算一个看似权威的部位最大值。难以准确量化的效果先写成条件化功能，不显示没有真实消费者的热量、疲劳或社交总分。

沿用总方案：常规耐久百分比维护退出，改完好、受损、不可用及有原因的维修。消耗品数量、弓箭/燃料等确实需要计数的资源可保留数量；不能把所有物品都变成耐久条。

## 6. 一个共用动作合同

拟议领域入口 `planInventoryAction` 同时服务 UI 与自然语言，返回可执行计划或具体障碍。输入包含 actor、场景、物件、来源、目标、数量、用途和所依据的事件/许可；不接受模型自行声明的 accessible=true。

处理顺序：

1. 从当前事务视图解析实体与所有权/保管/物理位置，确认物品确实存在。
2. 检查实际接近路径与储藏边界，再检查授权或非法行动分支。
3. 检查物件状态、用途、部位冲突、装载、旧物去向和时间/支付条件。
4. 生成唯一交接计划；取出并穿戴是同一计划的顺序子步骤，不先提交半次取出。
5. 按该动作结果轨统一提交物品状态、保管/权利变化、耗材/费用/时间、事件和可见认知。

UI 用同一个计划器的只读预检结果列出选项；正式执行带 worldRevision 再验证。别人先拿走、库房锁上或许可到期后，只读预检可以失效，实际提交不能继续按旧快照执行。

个人物品表与世界资产表不要各自判断成功。短期保持兼容投影但确立一个结算权威；长远让角色背包、仓库和世界资产成为同一物品/保管事件的不同视图。稳定实例 ID 及所有权历史原样保留，迁移不能把借来的物品洗成玩家自有。

场景模型上下文只注入当前穿戴、确实可取用物件、相关功能、已知储藏和正在进行的交接。远方库存全文、所有附魔标签和每个空装备槽不常驻上下文。物品秘密按观察者过滤；NPC 不因参与交谈就获知玩家背包里的全部东西。

## 7. UI 流程具体改什么

装备入口显示当前装束、影响行动的状态和一个“换装”动作；点具体物件可查看来源、用途、穿戴条件和放置去向。

仓库入口改成具体名称及保管关系，例如“白港客栈 · 掌柜寄存”“临冬城卧房 · 你的箱子”。清单旁标“亲自查看于昨日”或“管家三日前来信”。只有产权/使用权相关时展开法理/控制/保管字段，日常不在每张卡重复三个主体。

示例：玩家身在白港，想用临冬城箱中的甲。详情给出“留在临冬城；最后清点于五日前”，可选择写信请可信联系人运送，或在本地寻找借用/购买；不展示可立即装备按钮。送达后换装页面仍明确原衣物放何处。

示例：客人进入临冬城庭院，不会立即得到军械库的完整可操作列表。可以找军需官、请求借甲或选择潜入；获准进入后，允许统一取出并穿戴，不能再被“物品未直接保管”规则重复拒绝。

## 8. 实施与验收

先修 SE01 的预检/规划矛盾与 SE07 的自动去向，再引入场景访问、权限、统一取物计划，随后迁移落脚处和装备状态。此顺序不意味着把所有仓库权限暂时放开。

旧档：保留原 site 与 item ID；可以确定为公共军械库的沿用组织权利，明确私人箱子保留其来源。null 归属不能批量猜成领主或玩家；不确定数据保留待核对状态。旧容量和已发生历史不回溯重算；真实迁移前生成独立备份。

必需的新增回归：

- 同场、已获许可、同一件物品，UI 候选与正式计划一致；取出并穿戴原子完成。
- 同城不同房间不自动接触；远程直接穿戴拒绝，交接真正到达后才可用。
- 寄存保留产权；租住不会获得房屋产权；地方头衔易主不自动赠送所有私人储藏。
- 非法行动成败与普通取用分开；transfer/equip/use/gift 都使用相同的访问与知情事件来源。
- 调整 site 字典顺序不会改变换装旧物的去向；容量不足不给用户丢装备。
- 武器入鞘不占双手，拔出双手武器才占手；行李中的甲不提供保护。
- 预设不创造缺失物品，取消/重试不重复取物或付款，交接中的物品不能重复分配。
- 防护展示与对应条件下的实际解释相符；工具参与行动无须伪装成佩饰。
- 撤营、失去住处与被俘不会删物品；负担异常允许放下或转交，不能陷入无动作可用。

本轮现有 custody/equipment/action-choices/world-transactions 共 21 项测试通过；上述新探针也通过。现有测试覆盖局部算法，不足以证明 UI 到世界规划的完整链已经一致；新版规则仍需实现和端到端验收。

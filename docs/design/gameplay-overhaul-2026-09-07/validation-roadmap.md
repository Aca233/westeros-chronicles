# 重做顺序、退出计划与验收

状态：核心运行时已实施；本页保留为发布验证清单。真实模型长局、数值校准和真人试玩尚未执行，详见 [实施状态](../IMPLEMENTATION_STATUS.md)。

## 1. 优先级

| 阶段 | 必须交付 | 明确不同时扩张 | 退出门槛 |
|---|---|---|---|
| S0 结果可信 | 成败轨隔离、严格协议、在场证据、授权门槛、认知旁路封闭、伤势覆盖修复、特质统一 ID | 新美术、经营、魔法 | 高风险回归全过，旧世界不会因协议容错被改错 |
| S1 一个人能生活 | 真实地点建角、身份/联系人/资源、Scene、请求与答复、玩家目标、身份化选项 | 所有人物可开局、全新年代 | 侍从求见场景有三种方法、可信拒绝、可继续生活 |
| S2 人物会记得 | 承诺、认知来源、关系依据、通信、场景日志、长期召回 | 全大陆谣言模拟 | 私诺冲突持续 20 回合；第三人不知道没听见的事 |
| S3 代价真实 | 交易、物品用途、创伤治疗、有限冲突、旅行成本与时点、伙伴职责 | 全产业链/战棋 | 治疗/护送/失败被俘/返程是一条完整可玩链 |
| S4 身份改变世界 | 头衔授权、继承案件、局部组织议程、委派 Project、有限战役 | 全球战略 AI | 统治者与弱势人物通过同一规则面对不同权利与后果 |
| S5 长局与品质 | 新能力量尺校准、成长、正文质量、回顾/终局、旧档策略、模型预算 | 更多庞杂系统 | 100 回合回放、存档往返、真人盲评通过 |

S0 部分问题可独立修复；新能力量尺可先 shadow 测量，不必阻塞 S1。S2—S3 的交易/承诺/治疗最小合同应围绕同一竖切协同落地，不是严格各做完一整套才联调。

人格负担、复杂婚姻制度、非玩家大规模继承、龙/魔法等扩展只有在已有路径证明必要时进入后续交付。新增机制不以字段已经写出为完成，至少需要一个玩家能触发、拒绝、付出代价并见到后果的场景。

## 2. 旧机制退出清单

| 旧机制 | 替代与退出动作 | 需要保留的数据/能力 |
|---|---|---|
| ActionDock 三种逐行动检定模式 | 标准模式只保留统一裁定；显示偏好独立；沙盒另设规则档 | 旧回合的骰子结果与模式记录 |
| 400 点建角主界面 | 经历/身份建角稳定后退出主流程，保留高级编辑入口 | 名称、画像、家族纹章、原始能力与特质 ID |
| goldGain 泛化倍率 | 删除全局放大；相关特质转为有场景条件的议价/管理行为 | 原余额不倒扣，旧交易历史不重算 |
| 特质随机抗伤 | 移除被动触发，统一身体与风险结算 | 已发生伤势与历史结果原样保留 |
| 双路径特质文本/ID | 规范 ID 为权威，显示文本派生；旧文本做保守映射 | 未知旧标签保留为历史描述，不猜规则 |
| 0—100 玩家可升级能力显示 | 映射有效等级与专业资格，先做分布评估 | 原作源数值和迁移前数值留来源字段 |
| 0—100 耐久、点一次修 25 | 新状态与维修合同接通后撤下按钮和数值 | 旧值按显式表迁移并标记来源，不抹去受损经历 |
| 不指定目标的 use | 替换为明确用途表单/自然语言意图；不适用则隐藏 | 物品实例、数量、charges 与所有权 |
| 通用属性路线选项与领主模板 | 能力和身份驱动建议，默认“行动”称谓 | 自由输入与历史原文 |
| 原作未来/全量 NPC 记忆直显 | 玩家认知投影；资料库/调试层独立 | 原作档案与私有记忆仍保存在正确权限层 |
| 路线无闭环精确风险与费用 | 先改定性与明确预估；实装后按合同显示 | 原路径图与启发式权重可继续用于寻路 |
| 普通玩家直接头衔变更命令 | 只接收有授权的结算事件，自称/谋反独立处理 | 法理、控制、历史头衔和争议 |
| 模型完整思考文本 | 不再作为提示词输出要求与玩家内容；改事件/规则依据 | 历史存档兼容读取但不回注上下文 |

退出分三步：停止生成旧行为 → 新引擎提供替代并迁移数据 → 删除无消费者的旧代码/测试。不是为了保持旧测试绿而继续执行旧行为，也不能提前删除用户唯一的历史读取路径。

可选美术表现不必删除物理文件。先停止增加玩法无收益的 3D/地图复杂度，保留按需加载与降级能力。任何真正的资产清理都需先确认引用、存档兼容与可恢复来源。

## 3. 模块调整与权威边界

沿用上一套 [上下文实施方案](../roleplay-context-v2/implementation.md) 的 context/roleplay/memory/modelRuntime 目录建议，新增规则只在相应领域中扩展，不把所有逻辑继续堆入 Store。

| 原入口 | 目标职责 |
|---|---|
| `useGameStore.submitAction` | 锁定 attempt、编排领域服务、显示状态，不自行决定成败回退 |
| `diceEngine` / `dicePolicy` | 统一风险合同、来源去重、概率与回放；不靠关键词替代前置事实 |
| `stateReducer` | 接受经验证的变化，逐步让身体/金钱/特质归对应领域统一投影 |
| `worldTitleRules` / `worldPreparation` | 校验 AuthorityEvidence/ConflictOutcome，再转换变更；不能双方互相假定已授权 |
| `items/actions` | 保持数量与位置约束；use/repair 转为用途与服务合同执行器 |
| `journeyReducer` | 保留路线位置一致性，接入共同时间与资源/中断合同 |
| `characterDossier` / `useCharacterDossier` | 显式接收 viewer/time/knowledge，源头产生可见 ViewModel |
| `CharacterCreator` | 展示身份与经历选择，开局事实由领域服务创建 |
| `db.commitTurnAtomically` | 世界、社会、认知、场景、资源一体提交；派生记忆任务按版本异步 |

字段设计必须回答：谁写、谁读、哪个玩家行为改变它、哪个可见后果用到它、何时失效。如果一个新数值没有消费者和玩法案例，暂不加入存档合同。

## 4. 存档与回滚

重大规则变更按 engineVersion/rulesVersion 固定在周目上。旧档不能在没有转换的情况下突然采用新伤势、属性和资源语义。

建议采用“保留旧存档 → 创建新槽迁移副本 → 检查 → 继续”模式。能证明的世界事实保留，无法证明的旧小说承诺/身份只作历史文本，不自动升级为新权威。

属性映射、耐久映射、特质废止和旧货币字段都形成可审阅迁移报告。旧资金按原余额保留，不追溯扣除以前倍率收益；已发生事件不可用新规则重掷骰或重算死亡。

新增派生索引可重建，不能因此丢掉原始人物事件、秘密受众或遗留物品。导入重铸 runId 时重映射全部引用；撤回和分支复制包含个人知识、承诺、场景、异步摘要任务和随机记录。

支持兼容读取/导出旧档，再逐步退役旧执行引擎。若决定新引擎只支持新局，应明确显示并允许保留/导出原档，不静默清理旧链。回滚到旧引擎使用备份周目，新事件无法安全降级时不得强行加载。

## 5. 必须新增或改写的机制回归

这些测试验证玩家可能遇到的错误，不只复制实现细节。

| 编号 | 输入/情境 | 通过条件 |
|---|---|---|
| G01 | 旧重伤后再受轻伤；玩家与 NPC 各跑一次 | 严重限制不被擦伤覆盖，伤口记录各自保留 |
| G02 | 支付后等额退款、借款转入、账户转账 | 无任何性格乘法，类型/金额/来源一致 |
| G03 | 新增规范特质、未知标签、旧档文本迁移 | 显示和规则用同一投影，未知标签不凭空获得加成 |
| G04 | 同一来源同时作为能力/教育/特质/装备标签 | 去重并说明来源，不重复叠加 |
| G05 | 数值超过量尺、不同档位、固定 DC 全点数枚举 | 展示等级与实际概率一致，参数变更有分布报告 |
| G06 | 无权人物自封、合法授权、已有控制但无承认 | 分别产生宣称/合法授予/争议，不能都改成合法持有 |
| G07 | 婚姻条件缺失、提出婚约、正式履行 | 状态仅在有效成立事件后改变，模型不能自动代玩家同意 |
| G08 | 没有在场证据，只有提及/同城/旧交互 | 不得直接伤害/赠礼/读取私密回应 |
| G09 | NPC secret/restricted 记忆进入档案与 UI | 正常 DOM、搜索、摘要、模型包均不可见 |
| G10 | 使用绷带但无伤口/无用量；工具按用途使用 | 无效操作不消耗；合法治疗资源与疗效同组结算；非耗材不凭空消失 |
| G11 | 修理缺工具/人手/时间/费用 | 不恢复装备；明确可行替代与所需条件 |
| G12 | 交易双方交割、缺款、对方拒收礼物 | 不免费得物，不在拒收后仍改所有者 |
| G13 | 盗窃失败、未发现成功、发现丢失、查明窃贼 | 状态和知情范围分别正确，失败轨没有成功资产变更 |
| G14 | 反复同条件说服、赠礼、无风险训练 | 不重骰刷成功，不无限刷关系或成长 |
| G15 | “明天再谈”与明确“明日归还”，期限前/后 | 不混同闲谈和义务；到期有证据与宽限判断 |
| G16 | 信件送出、途中截获、到达、收到但不信 | 区分消息事件与角色认知，未收到者不先知 |
| G17 | 旅行选择无可用交通方式或未同意同行者 | 规则层拒绝对应部分，不能仅依赖 UI 隐藏按钮 |
| G18 | 路费/资源锁定后出发、中断、改道、取消 | 按约定阶段结算，不重复扣费或免费跨越 |
| G19 | 长途跳过多个日期，途中有早于终点的期限 | 停在最早需要决策的事件点，后续不擅自推进 |
| G20 | 夏季日期变更但世界仍长冬 | 天气/季节/日期职责独立，路线不因措辞变化漂移 |
| G21 | 战败、投降、被俘、释放、死亡 | 合同内后果成立且可继续相应流程，玩家/NPC同规则 |
| G22 | 自建弱势人物与领主开局 | 真实地点、资源与身份匹配；无凭空封臣/关注/城堡 |
| G23 | 伙伴被委派，遇风险/信息变化/职责冲突 | 依据权限与目标回应，消息按渠道到达，不能操纵未知事实 |
| G24 | 原作节点前置改变、未改变、不足以相关的变化 | 仅相关条件影响节点，不一刀切阻止或强制复演 |
| G25 | 简单换装、危险场景换甲、查看卷宗 | 分别按实际耗时/风险/无时间处理，世界事件仍统一提交 |
| G26 | 模型或 DB 失败、取消、重试、刷新恢复 | 不变更已提交世界，不丢输入，不重骰，重复提交幂等 |
| G27 | 撤回之后延迟消息或摘要返回 | 废弃分支任务不污染当前世界 |
| G28 | 魔法梦境、合法有限能力、无授权骑龙 | 不把预兆当真相、不无限施法、不直接把龙当装备 |

已有测试需要保留的能力包括唯一归属、同地可达、旅行原子移动、地图失败降级、存档隔离与导入往返。已有测试需要改写的包括收益倍率、随机抗伤、缺协议默认成功/不检定、自然极值与旧 UI 模式。

## 6. 三条完整试玩路线

### T1：介绍信与机会（建议 10—15 回合）

自建弱势人物在真实地点开局 → 求见被挡 → 出示介绍信 → 信源待确认 → 选择等候/找担保/另谋机会 → 接到有期限的差事 → 确认旅费与方式 → 完成或错过 → 再见守卫/总管。

观察：是否存在真实身份差异；非暴力方法是否有效；失败能否形成下一步；信物和人物是否被记住；是否无端获得爵位或人脉。

### T2：私诺、公事与误解（建议 20—30 回合）

私下承诺 → 公开职责冲突 → 第三人只获得部分消息 → 调查来源 → 发送说明 → 信息延迟 → 履约、改约或违约 → 后续重逢。

观察：秘密受众、语言条件、口头请求与承诺的区别、关系变化理由、NPC 是否有自己的判断、是否代写玩家台词。必须至少走一次诚实解释路线与一次隐瞒路线。

### T3：委派、资源与失利（建议 20—30 回合）

有权人物收到两项相冲突请求 → 预算不足 → 委派调查/协商 → 路程与消息产生时间成本 → 一项行动受阻或发生有限冲突 → 支付/治疗/赎回/调整计划 → 回顾对组织与个人关系的影响。

观察：钱是否真的约束选择；指派是否需要权限；暴力是否有非死亡结局；伤势/物品/旅行是否闭环；失败后能否继续扮演。

至少一条路线延长到 100 回合并混入存档导入导出、撤回、新分支、模型暂时不可用与地图不可用。扩展场景保留自由输入，不只机械点击策划好的按钮。

## 7. 质量、复杂度与发布门槛

| 维度 | 如何量 | 门槛/方向 |
|---|---|---|
| 世界可信 | G01—G28 与关键边界断言 | 全部必需断言通过；错轨、泄密、重复扣费、无权改状态阻止发布 |
| 选择有效 | 每条路线至少三种有不同方法/代价的尝试 | 不能只有一个系统认识的关键词，不能所有选项同一结果 |
| 人物自主 | 人工逐场景标 NPC 诉求与回应依据 | 拒绝、让步、记仇、履约能从记录解释 |
| 玩家自主 | 标注代写决定/台词/动机 | 固定验收集零重大代行行为 |
| 长期连续 | 必需承诺/身份/认知召回 | 关键事实全部保留；错认与过期信息有来源可纠正 |
| 日常负担 | 一次常规换装/出发/查记事的操作数 | 比现有流程下降，且不牺牲归属/授权；实测后定具体指标 |
| 节奏 | 无实际变化的重复回合、无事旅行提交次数 | 无事旅途无需逐日输入；闲谈允许自然停留，不强制推进指标 |
| 质量 | 盲读新旧同输入的正文 | 角色区别、回应、因果、自然程度分项评价，不能只评价华丽文笔 |
| 模型成本 | 各阶段 token、调用数、p50/p95 与修复率 | 普通叙事默认两调用，小动作可零模型；先测基线再定延迟上限 |
| 稳定 | 存档往返、取消恢复、分支隔离 | 世界/人物/知识/资源相符；100 回合不线性膨胀上下文 |

发布报告必须写样本数和失败案例。任何“零失败”都仅限实际运行的样本；不能称作所有中文表达都通过的证明。

每增加一个机制都要填一张简短交付卡：触发、玩家选择、规则依据、状态改变、反应、后续召回、失败/取消恢复、测试样例。没有这张卡就不标记为“已实现玩法”。

# 全游戏 UI/UX 改革方案

状态：主行动流、抽屉、人物卷宗、资产管理和死亡回顾已接入运行时；发布体验验证见 [实施状态](../IMPLEMENTATION_STATUS.md)。目标是支持长期角色扮演、中文阅读和有后果的行动；人物细节另见 [人物信息与面板](character-panel.md)。

## 1. 当前体验的主要问题

当前 App 以顶栏、局势走马灯、正文列、底部 ActionDock 和左右边缘抽屉入口组成主界面。地图、人物、物品和设置多通过抽屉/模态层展开。这种正文优先的根基值得保留，但入口、状态和操作需要重新组织。

源码依据：`src/App.tsx`、`src/components/StoryFeed.tsx`、`ActionDock.tsx`、`Ck3CharacterWindow.tsx`、`CharacterCreator.tsx`、`menu/NewGameScreen.tsx`、`menu/LoadGameScreen.tsx`、`features/map/MapDrawer.tsx` 与 `components/items`。以下区分已见行为和新设计选择；尚未进行真实用户访谈或量化可用性实验。

| 当前行为/结构 | 对角色扮演的影响 | 改革决定 |
|---|---|---|
| 人物与地图依赖边缘竖签和快捷键 | 核心查询入口需要发现，手机边缘操作受限 | 持续可见的中文导航，保留可选快捷键 |
| 地图/人物作为覆盖正文的模态抽屉 | 查询人物时难以对照正在阅读的对话 | 宽屏并排详情；窄屏专页并保留返回位置 |
| 变化日志重复滚动展示 | 短暂的消息争夺阅读注意力，变化未必清楚属于哪次行动 | 与对应正文绑定的静态“这一回合”摘要，通知仅在有新可见消息时出现 |
| 所有人输入称“御令” | 预设玩家掌权，限制弱势角色的表达 | 默认“你的行动或话语”，按场景提供有对象的草稿 |
| 输入为单行，提交立即清空 | 长对白难修改，失败时输入恢复依赖额外机制 | 可伸展多行输入；确认提交后归档草稿，失败原文可恢复 |
| 数字键 1–6 直接提交分支 | 浏览界面时可能误做有后果的行动 | 数字键只选择并预填；明确执行键才提交 |
| 回合结束自动聚焦输入 | 可能打断用户阅读/查询 | 仅用户在输入区发起且未移开焦点时恢复；其他情况提示完成 |
| 每回合三个骰子模式图标 | 把规则控制混进角色行动，图标含义需解释 | 规则模式放在开局/设置，主游玩只表达行动；骰子细节按需查看 |
| 启动失败页提供“清空本地存档并重试” | 一般故障恢复路径过度破坏性 | 重试、导出可读数据、选择其他存档和诊断在前；清空是独立末级操作 |
| 懒加载详情采用空 fallback | 初次打开可能缺少明确反馈 | 即刻出现标题与加载状态，失败可重试并返回 |
| 原作未来时间线可在默认游戏内切换 | 玩家知识与角色视角混杂 | 游戏内只显示本人获知的消息与经历；原作参考在周目外明确标注 |
| 阴影、粒子、游标光效和揭幕叠加 | 长时间中文阅读的负担增加，低性能设备额外开销 | 保留克制材质，动态装饰默认弱化；支持减弱动态与纯净阅读 |

## 2. 新的一级导航与信息归属

只设五个常用目的地：**故事、人物、行囊、地图、手记**。设置、存档和返回标题屏进入菜单；统治者的政务作为身份能力入口出现，不占所有人物的一级导航。

| 目的地 | 玩家来这里做什么 | 禁止重复建设 |
|---|---|---|
| 故事 | 阅读当前场景、说话、行动、承接后果 | 不常驻完整六维属性、库存和世界新闻表 |
| 人物 | 找到已认识的人，回顾交情、接触对方 | 不直接列出全部世界实体及秘密 |
| 行囊 | 使用、装备、借还、托管可支配物品 | 不与身体页/人物页各维护一套不同状态 |
| 地图 | 确认已知位置、比较可行路线、理解距离 | 不把战略资源面板强加给旅行者 |
| 手记 | 看未了之事、信件、亲历记录与个人笔记 | 不复制全量世界事件数据库 |

“手记”中的未了之事只包含玩家已知的承诺、明确诉求和玩家自行记录的打算。不要因为 NPC 后台有阴谋，就自动生成任务卡。目标可放弃；失约后果来自世界规则。

## 3. 主游玩界面

桌面：顶部简短显示自己、地点、时刻和保存状态；主体为舒适宽度的正文；下方为当前行动输入。人物/物品证据查询在宽度足够时打开可固定侧栏，正文仍可阅读与操作。没有打开详情时不预留空侧栏。

手机：顶部保留场景与必要状态，底部可见导航；行动输入与软键盘配合，避免同时叠上五行选项和巨大面板。详情是可返回的页面。安全区域与键盘顶起后，执行键与取消键都能到达。

正文按场景和行动段落组织，而非每一拍都是同规格大卡片。清楚区分玩家发言、角色对白和叙述，但不为每个 NPC 搭一整套聊天气泡。人名与物件可轻量点查；链接样式克制，有键盘焦点和触控反馈。

每回合结束仅显示有意义的已知后果，例如“你交出了封蜡信；守卫答应引见”。金币、伤势等具体变化与相关内容关联，允许展开规则详情。无变化时不生成空摘要；暗中发生而玩家未获知的变动不显示。

正在读旧段落时不自动滚到底；底部“有新内容”按钮提供跳转。流式文字到来保持用户当前阅读锚点。新场景可自然显示地点/时间分隔，不每次重复家族和背景。

## 4. 输入、建议与有后果的执行

默认自由表达，支持动作与对白混合。建议通常 0–3 条，确有分歧时才生成；其文本说明策略或态度，不保证结果、不替玩家签约。选择建议进入草稿后可以修改，再按执行。

面板动作带入对象和必要参数，例如“把这封信交给守卫，请他代为引见”，不是立即提交一串隐藏命令。近期草稿按周目保留；敏感本地文本不进入遥测。新草稿不覆盖已有输入，提供插入或替换选择。

普通行动不弹二次确认。只有已发现的重大新代价、不可逆存档删除、大额明确交易或超出原意图的承诺需要额外确认；确认必须展示具体对象、代价和后果。原先已经表达的同意不重复询问。

游戏能知道的确定费用可以预先展示；隐蔽风险不变成精确赔率。尝试社会行为时不能提前显示“对方必定拒绝”来泄露隐藏意图。检定结果可展开依据，成功率只在规则明确且没有泄露秘密时显示。

输入法组合输入期间 Enter 不提交。默认 Enter 换行，Ctrl/Cmd+Enter 执行，并在设置允许改键；按钮始终可用。全局快捷键在对话框、输入框和屏幕阅读器交互期间不抢占。

## 5. 回合状态、取消与失败恢复

| 状态 | 用户看到什么 | 可以做什么 |
|---|---|---|
| 草稿 | 原文、目标对象、明确的已知费用 | 编辑、查资料、执行 |
| 接受请求后 | 原文保留，“正在处理你的行动” | 继续查资料；尚可取消时显示取消 |
| 草案生成/校验 | 克制的进度说明，无伪造百分比 | 取消；不会把未验证文本写成已发生事实 |
| 正文准备 | 合格正文可逐步呈现，未完成标记清楚 | 依事务合同决定取消，不宣称已发生不可提交的结果 |
| 原子提交 | 短暂“正在保存这一回合” | 防重复提交；不把取消按钮伪装成仍可撤销 |
| 成功 | 正文、相关后果、保存完成 | 下一行动，查看依据或创建分支 |
| 失败 | 保留草稿，说明发生在提交前还是提交后 | 提交前安全重试；已提交仅重生成正文/恢复显示，不重复扣款 |

具体阶段命名必须与最终事务模型对应，不能只改 UI 文案。网络断线、限流、格式无效、取消、页面关闭和崩溃恢复分别覆盖。错误详情收在展开区，默认不展示密钥、完整提示词或供应商堆栈。

“重写这段文字”只改表达，不能改已落定结果；“从这里另开分支”复制历史节点并明确新的分支。两者不能共用一个含糊“重试”按钮。真实提交仍以幂等 requestId/turnId 和存档事务为准。

## 6. 地图、旅行、物品与身体

地图默认服务当前地点与目的地。只显示角色已知的动态情报；地理基础知识由出身和资料设定提供。当前位置与远方消息的位置明确区分。目的地选择 → 可行路线 → 已知耗时/资源 → 确认启程，途中才进入实际场景与事件。低性能/加载失败提供地点列表和路线文字摘要，核心旅行不依赖三维效果。

行囊默认以用途和保管位置组织：随身、托管、借出；重要个人物件突出来历。普通补给合并显示，装备状态直接可见。选择治疗用品必须选择适用伤势与用量，修理必须呈现服务/材料/时间合同。远方仓库只可查询已知清单和发起调拨，不能直接穿戴。

身体详情先显示“当前行动影响”和处理办法，再显示伤口/部位。解剖图是可选导航，所有内容另有文本列表。区分稳定、恢复中、已愈和遗留影响，不用彩色人体图充当唯一解释。

头衔、城堡、军队、预算只在有相应身份时提供入口。授权、委派、收到报告和下达请求各有事件依据；在个人钱袋旁塞一排领地数字无法替代政务玩法。

## 7. 建角、开局与人生结束

建角改为四步：选择原作人物或自建身份 → 填充出身与重要牵连 → 确认自己的打算与底线 → 查看开局处境并进入。原作角色可以直接接受推荐处境，避免被迫重新填写所有关系。

每步均显示选择对可做之事的影响，例如出身决定识字/联系人/起始资源范围。允许返回修改；未填项目可使用明确默认项。名字、年龄、所属家族、初始地点与时间必须一致，不能出现任意城堡文案配未知地图 ID。

初始金钱、物件、能力和社会关系从身份模板与具体经历生成，由规则校验。高级沙盒编辑作为明确独立入口，不与标准玩法平衡承诺混同。模型/密钥配置提供连接测试与清楚错误；无连接时可浏览说明，但不伪装能开始真实生成。

第一场必须可立即扮演：眼前有人、一件可回应的事情和可理解的处境。引导嵌入第一次查询人物、选择行动和看到后果，不连续弹教程。弱势人物、游历者与统治者各有测试开局。

人生结束页展示此人重要选择及有证据的影响；提供保存回顾、回到既有分支、另开人生和返回菜单。尚未实现的继承机制只作为后续设计，不能显示会丢状态的伪入口。

## 8. 存档与设置

存档卡以人物、日期、地点、最近一件事与分支关系帮助辨认，辅以最后保存时间。自动保存、手动快照和分支清晰命名。导入先检查版本与完整性，预览后创建新槽；禁止默认覆盖当前周目。迁移前保留旧文件，失败仍可导出。

启动失败恢复路径：重试 → 选择其他周目/进入无存档菜单 → 导出可读取数据与诊断 → 单独选择删除损坏存档。清空全部需列出影响范围并由用户明确确认；UI 操作的危险程度应与按钮样式匹配。

设置按“阅读与操作、游戏规则、模型连接、存档与数据”组织，调试独立折叠。文风、正文长度、字体、对比度与动态效果可预览；变更规则模式需明确适用周目和时点。不要把叙述详略、模型能力和掷骰规则塞进同一个“模式”。

## 9. 视觉与无障碍方向

保留墨色、羊皮纸、朱红和少量金属色的世界气质，减少噪点、装饰框、悬浮光和持续动画。正文排版决定主要品质：舒适行宽、明显段落间距、足够对比、稳定字体回退。明暗主题均以实际文字对比度验证。

起始候选：正文 18px、可调 16–22px，界面正文 14–16px，辅助字不低于 13px；中文正文行高约 1.7–1.9。最终以桌面、手机和 200% 缩放实测调整。不能靠整体缩小字体塞入旧栏目。

交互目标触屏至少约 44px；状态用文字配合颜色。实际产品对话框实现正确焦点约束、关闭后返回触发点、Esc 只关闭最上层；固定侧栏不冒充模态对话框。尊重减少动态偏好；错误摘要可由辅助技术读取，但逐字流式内容不连续播报。

这些是产品实现规格。当前交互预览只演示信息架构和流程，不能替代真实设备与辅助技术验收。

## 10. 实施顺序与体验验收

1. 先封闭数据可见性、原子提交、草稿恢复与损坏存档的恢复路径；这些是 UI 可信度基础。
2. 替换输入、建议选择、回合状态和阅读锚点，保持一次完整行动可用。
3. 落地人物投影与新面板，再加入人物名单/手记作为同一已知信息的不同入口。
4. 替换导航、宽屏详情与手机详情路由，统一返回栈；随后迁移行囊、地图和政务入口。
5. 替换建角/存档流程，再收尾字体、材质、图标、主题和低性能模式。每阶段删除已经被替代的旧入口，避免长期双轨。

验收采用代表场景和计时任务，以下是目标而非已达成数据：

- 新玩家在 30 秒内找到眼前人物、自己的待履行承诺和自由输入；无需知道 C/M 快捷键。
- 查询一个人物后返回原文，阅读位置、输入草稿和选中对象全部保持。
- 完成“取出绷带 → 选择伤势 → 治疗”，治疗、耗材与时间只有一次原子结算。
- 途中断网后恢复原草稿；已提交但显示失败不会再次扣除资源。
- 360px 与 320px、软键盘弹出、200% 缩放、纯键盘场景都能完成主行动与返回；无双层滚动陷阱。
- 玩家读旧文时，长正文流式生成不抢滚动和焦点；减少动态模式无自动跑马灯。
- 前端视图、无障碍文本、搜索/地图摘要和导出手记均不暴露未获知秘密。
- 三类身份完成首场无需理解属性公式；建议选择不会意外立即执行。
- 损坏一个存档不会迫使删除其他周目；导入/迁移均有可恢复副本。

原型选用人物详情作为首个可检查界面，随后实现时依以上顺序做主游玩闭环。不能从一张好看的面板推断全局可用性已经解决。

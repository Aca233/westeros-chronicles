# 普通物品归属权威清理设计

## 目标

清除普通玩家物品实例中的旧归属字段，使物品的法理所有者、控制者、保管者和世界位置统一由 `WorldRuntimeState` 表达，避免普通物品同时存在实例字段与世界资产关系两套权威。

## 本轮范围

- 从 `ItemInstance` 删除 `lawfulControllerId`。
- 删除内置普通物品预设中的该字段。
- 赠送物品时，物品玩法状态只更新数量、人物持有位置和历史；世界资产关系由既有世界事务更新。
- 堆叠合并不再比较旧归属字段，仍要求定义、位置、耐久、品质、次数、自定义名称、名望、传家宝状态及独立历史兼容。
- 物品卡来源信息不再显示实例中的“合法归属”。需要展示归属的世界资产界面继续读取 `WorldRuntimeState`。
- 存档格式从 8 提升到 9；不迁移旧测试存档，旧存档按现有策略要求重置。
- 增加静态边界测试，防止普通物品模块、普通物品预设和普通物品测试重新引入 `lawfulControllerId`。

## 明确不在本轮处理

- 不删除 `WorldArtifactRecord.lawfulControllerId`。该字段属于 AGOT 世界神器导入记录，是建立世界资产基线的输入，不是普通 `ItemInstance` 的旧字段。
- 不删除 `ItemSystemState.placements`。装备槽、容量、使用和物品转移仍以它作为玩法状态；将其迁移为 `WorldRuntimeState` 投影需另立规格。
- 不修改地图、瓦片、模型或生成资产。

## 数据流

普通物品动作继续通过现有统一事务管线执行：

1. `ItemAction` 更新 `ItemSystemState` 中的数量、玩法位置和历史。
2. 世界事务队列将赠送等动作解析为世界资产意图。
3. 世界事务更新 `WorldRuntimeState.assets[assetId]` 的 `lawfulOwner`、`controller`、`custodian` 和 `placement`。
4. 资产归属界面与人物资产查询只读取世界运行时关系，不回退到普通物品实例。

## 兼容与错误处理

- 版本 8 及更早测试存档均被拒绝，并显示现有“重置测试存档”提示。
- 世界神器导入与历史投影仍可保留并读取其导入记录中的 `lawfulControllerId`。
- 普通物品赠送失败仍保持整批动作原子回滚。

## 验证

- 普通物品边界检查确认旧字段仅允许出现在世界神器导入域。
- 物品动作测试确认赠送后不存在实例归属字段，人物持有位置和赠送历史正常。
- 合并测试确认不依赖实例归属字段。
- 物品视图测试确认不再显示旧“合法归属”。
- 存档测试确认版本 9 接受、版本 8 拒绝。
- 世界事务与事务队列测试确认赠送仍更新世界资产关系。
- 最后运行 TypeScript 类型检查和代码构建。

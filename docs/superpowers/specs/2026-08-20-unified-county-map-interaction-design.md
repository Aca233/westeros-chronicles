# 统一伯爵领地图交互设计

日期：2026-08-20
状态：已实现；其中三级标签表达已被五级头衔地图规格取代

## 1. 背景

现有地图同时提供“地形、政治、人物、旅行、资产”五种互斥模式，但这些入口混合了三类不同概念：底图表现、信息图层和操作流程。切换模式会同时改变底图明暗、道路、政治填色、人物点、资产点和路线可见性，导致玩家无法稳定预期一次点击会执行区域下钻、选择地点、打开人物还是规划旅行。

现有政治点击还保留“帝国→王国→公国→伯爵领”的逐级展开状态，与已经确定的“伯爵领是最小且主要政治交互单位”相冲突。地图内部用伯爵领首府地点代替伯爵领选择，也使伯爵领详情、具体地点详情和旅行目的地在状态层混为一体。

本设计把地图改为一张自动表达战略层级的地图：伯爵领承担统一区域选择，人物与资产成为受密度约束的信息图层，旅行成为由详情面板发起的操作。地图不再要求玩家先选择正确模式才能点击目标。

本设计替代以下旧决策：

- `2026-08-18-agot-map-system-design.md` 中的五种互斥地图模式。
- `2026-08-19-ck3-semantic-map-zoom-design.md` 中“缩放不得改变地图模式”和“五种模式保持不变”的要求。
- 现有帝国、王国、公国逐级点击展开路径。

离线地图数据、伯爵领语义几何、统一地点权威、动态政治投影和世界旅行结算继续保留。

## 2. 目标

1. 删除五种地图模式，建立无需预先切换模式的统一点击逻辑。
2. 远景表达政治局势，中景以伯爵领为主要交互层，近景表达选中伯爵领的内部地点。
3. 点击任何政治区域都能直接选中伯爵领，不再逐级展开帝国、王国和公国。
4. 明确区分伯爵领选择和伯爵领内具体地点选择。
5. 人物与资产只在当前选中伯爵领内按缩放密度显示，不铺满大陆。
6. 旅行由伯爵领或地点详情发起，不再作为地图模式。
7. 保留地点搜索、俯视和归北，并把非互斥信息集中到一个“地图信息”入口。
8. 正文地点链接、人物卷宗所在地、资产位置和时间线事件继续使用相同稳定地点 ID。
9. 在减少视觉和操作状态的同时降低动态人物、资产和政治数据的无效重算。

## 3. 非目标

1. 本轮不新增军队、战争迷雾、补给、建设或领地管理玩法。
2. 不重新导入或重做地图几何、地形贴图和离线瓦片。
3. 不实现男爵领可见层；`baronyId` 继续只作为内部数据映射键。
4. 不让 LLM 直接控制地图 UI 状态或绕过旅行结算改变人物位置。
5. 不兼容旧测试版的 `mapMode`、`titleExpansion` 等纯 UI 状态。
6. 不改变人物、资产、政治、旅程和世界时间线的权威数据结构，除非为统一选择引用增加只读投影。
7. 不在地图关闭时继续维护 MapLibre 实例或动态图层。

## 4. 备选方案与决策

### 4.1 方案一：缩减为三个模式

保留“浏览、人物、旅行”三个模式。优点是改动较小，缺点是人物和旅行仍会改变点击语义，玩家仍需猜测当前状态。本方案不采用。

### 4.2 方案二：统一地图、上下文图层、旅行操作

地图本身只有一套浏览逻辑，缩放决定战略表达，人物和资产是独立图层，旅行从详情面板发起。该方案在可预测性、信息控制和现有系统复用之间最平衡，本设计采用此方案。

### 4.3 方案三：完全自动且没有信息控制

所有信息按算法自动显示，不提供图层入口。画面最简，但玩家无法主动调查某类信息，也难以解释信息为何缺失。本方案不采用。

## 5. 核心交互模型

### 5.1 唯一浏览规则

普通浏览状态下，每类对象始终只有一种点击结果：

- 点击地图政治区域：直接选中该位置所属伯爵领。
- 点击伯爵领内地点图标：选中具体地点。
- 点击单个人物标记或人物列表项：打开人物卷宗。
- 点击单个资产标记或资产列表项：打开资产详情。
- 点击聚合标记：打开对应地点或伯爵领的筛选列表，不自动选择第一项。
- 点击没有任何可交互要素的空白：清除具体地点和伯爵领选择，保留视野与图层偏好。
- 按 Escape：依次取消旅行改点、关闭路线规划、关闭具体地点详情、关闭伯爵领详情；最后一次才关闭地图抽屉。

人物、资产和地点图层必须阻止点击事件继续落到下方伯爵领命中层，避免一次点击同时打开两个对象。

### 5.2 旅行改点状态

地图只允许两个交互状态：

```ts
type MapInteractionState = 'browse' | 'pick-travel-destination'
```

`pick-travel-destination` 只改变伯爵领点击后的附加结果：新伯爵领成为路线候选目的地。它不改变底图、人物资产显隐或地点点击含义。界面必须持续显示“正在选择目的地”及取消入口，不能形成不可见模式。

### 5.3 选择状态

地图 UI 明确保存：

```ts
interface MapSelection {
  countyId: string | null
  locationId: string | null
}
```

约束如下：

1. `locationId` 非空时，其语义 membership 必须属于 `countyId`。
2. 选择新伯爵领时清空旧 `locationId`。
3. 选择具体地点时同时写入其 `countyId`。
4. 伯爵领选择不得再用首府 `locationId` 代替。
5. 伯爵领旅行目标可以解析为该伯爵领的稳定主要地点，但该解析只发生在路线请求边界，不改写当前选择语义。

外部跳转使用统一焦点请求：

```ts
type MapFocusTarget =
  | { kind: 'county'; countyId: string }
  | { kind: 'location'; locationId: string }
```

正文地点链接、人物所在地和资产位置仍可只提供稳定 `locationId`；地图通过 semantic membership 解析并同时选中父伯爵领。

## 6. 缩放与视觉表达

### 6.1 远景

- 显示地形远景底图、政治归属色块、争议边界和战略区域或王国级名称。
- 不显示人物点、资产点、伯爵领内部地点和旅行候选标记。
- 伯爵领命中仍可用：玩家点击任意区域后直接得到该处伯爵领并打开详情，但地图不自动改变缩放；玩家继续拉近后再展开内部地点。

### 6.2 中景

- 伯爵领边界与名称成为主要表达。
- 政治填色退场，地形成为主要表面；当前选中伯爵领保留清晰描边。
- 不显示未选中伯爵领的内部地点。
- 人物与资产主要通过伯爵领详情面板列出；地图只允许地点级聚合标记。

### 6.3 近景

- 只展开当前选中伯爵领内的城堡、城市、村镇和其他有效地点。
- 允许人物与资产图层在当前伯爵领内展开，但必须遵守密度上限和聚合规则。
- 未选中伯爵领继续保持安静，不显示内部地点或动态图标。

### 6.4 转换方式

政治表面和地形表面使用明确缩放阈值切换，不进行长区间透明度混合。阈值附近可以使用极短样式过渡防止闪烁，但两种表面不得长时间同时叠加导致发灰。边界、标签和地点可以保留各自短距离语义显隐。

缩放只改变信息密度，不改变交互状态、选择对象和工具栏布局。

## 7. 人物与资产密度

工具栏中的“地图信息”面板提供独立开关：

- 已知人物
- 据点与运输工具
- 道路
- 政治归属

默认值为人物开启、资产开启、道路开启、政治归属开启，但人物和资产受到以下强制限域：

1. 没有选中伯爵领时不显示人物和资产动态图标。
2. 只查询和渲染当前选中伯爵领内的已知人物与资产。
3. 中景按具体地点聚合，同一地点同一类别最多一个标记，并显示数量。
4. 近景优先显示与玩家、当前事件或当前地点有关的条目；其余仍按地点聚合。
5. 单类动态图标超过视野预算时继续聚合，不允许依靠缩小图标塞满画面。
6. 所有完整人物和资产列表均在伯爵领或地点详情中可访问，地图标记不是唯一入口。
7. 死亡人物、未知位置、传闻位置和过期情报遵守既有情报可见性，不因图层开启而泄露。

首版视野预算为人物最多 8 个独立标记、资产最多 6 个独立标记；超出预算的项目按地点聚合。预算集中定义，可在性能与可读性测试后调整。

## 8. 工具栏

横向五模式标签删除。常驻工具栏只保留：

1. 地点搜索。
2. 地图信息。
3. 俯视切换。
4. 归北。

“地图信息”使用高质量图标和文字标签打开小型面板，各图层是复选开关而非单选标签。面板关闭后不占据地图主要空间。

如果设备不支持三维地形，俯视继续禁用并显示现有二维地图说明。归北只重置 bearing，不改缩放、选择和图层。

## 9. 伯爵领与地点详情

### 9.1 伯爵领详情

点击伯爵领后首先打开伯爵领面板，至少包含：

- 伯爵领名称、所属公国和战略区域。
- 当前公开领主与实际控制者。
- 争议状态和已知近期事件。
- 主要地点列表。
- 当前已知人物列表。
- 据点与运输工具列表。
- “前往这里”入口，目标解析为伯爵领主要地点。

人物和资产列表项直接打开对应卷宗；用户不必依赖地图小图标。

### 9.2 具体地点详情

点击伯爵领内部地点后，在保持伯爵领上下文的前提下打开地点详情，包含该地点的描述、在场已知人物、在地资产和“前往这里”。关闭地点详情后返回同一伯爵领面板，而不是清除整个选择。

### 9.3 抽屉返回行为

从地图打开人物或资产抽屉时保留地图选择、视野和图层偏好。返回地图后恢复原伯爵领与地点，不重新飞行或重建选择。

## 10. 搜索与外部跳转

搜索结果根据类型执行：

- 伯爵领结果：选中伯爵领并定位到中景。
- 城堡、城市、村镇等地点结果：解析父伯爵领，同时选中具体地点并定位到近景。
- 不向玩家显示内部 `b_`、`c_` 等稳定键。

正文地点链接、人物卷宗所在地、资产详情所在地和时间线地点调用同一 `MapFocusTarget` 流程。外部定位允许飞行；地图内部点击不得无故改变当前缩放或倾斜。

无法解析父伯爵领时，地图可以把镜头定位到具体地点坐标，但不把该地点写入正式选择状态；同时显示“伯爵领资料未记录”，不得用家族驻地或法理头衔猜测。

## 11. 旅行流程

### 11.1 发起

- 伯爵领面板“前往这里”使用主要地点作为路线目标。
- 具体地点面板“前往这里”使用该地点作为路线目标。
- 当前地点与目标相同且没有内部移动需求时禁止建立跨地图旅程，并给出自然说明。

### 11.2 预览与确认

路线预览出现后，面板提供：

- 确认路线
- 修改目的地
- 取消

“修改目的地”进入显式 `pick-travel-destination` 状态。点击新伯爵领后只更新预览，不直接提交世界事务。确认后继续使用统一世界事务队列，在下一次成功对话后结算既有待处理动作规则。

### 11.3 已有旅程

已有进行中旅程时，路线、已走路段和当前位置始终显示，不依赖图层开关。普通浏览和查看人物资产不会隐藏旅程。重新规划与取消仍通过旅行面板和世界事务队列完成。

### 11.4 错误与取消

路线不可达、资料缺失或路线 worker 失败时只关闭无效预览并显示错误；不改变人物实际位置、不清除当前伯爵领选择，也不进入隐藏状态。取消改点后恢复原路线预览。

## 12. 状态与组件边界

### 12.1 MapUiStore

移除：

- `mapMode`
- `TitleExpansion`
- `titleExpansion`
- `expandTitle`
- `clearTitleExpansion`

新增或替换为：

- `selection: MapSelection`
- `interactionState: MapInteractionState`
- `overlayPreferences`
- `focusTarget` 或等价的一次性外部定位请求
- 显式选择伯爵领、选择地点、清除地点、清除全部选择、开始改点和取消改点动作

这些状态只属于 UI，不进入游戏存档的权威世界状态。

### 12.2 MapCanvas

MapCanvas 负责：

- 根据 zoom 阈值同步自动底图表达。
- 把省份命中映射为伯爵领并直接选择。
- 只展开选中伯爵领内部地点。
- 阻止前景对象点击穿透。
- 按选择伯爵领和图层偏好同步人物、资产聚合。
- 渲染旅程和路线预览。

MapCanvas 不负责构造伯爵领详情，不直接提交旅行事务。

### 12.3 MapDrawer

MapDrawer 负责：

- 解析外部 focus target。
- 加载选中伯爵领所需政治、人物和资产投影。
- 在伯爵领详情、地点详情和旅行面板之间组织返回关系。
- 把稳定选择和投影数据传给 MapCanvas。

### 12.4 MapToolbar

MapToolbar 只负责搜索、图层偏好和相机控制。它不知道旅行事务、人物详情和资产详情。

### 12.5 详情与旅行组件

现有 `LocationDetails` 中混合的伯爵领世界信息与地点详情拆开：

- `CountyDetails`：伯爵领级信息和列表。
- `LocationDetails`：具体地点信息。
- `TravelPlanner`：只消费明确的目标地点，不再依赖地图模式。

## 13. 数据流

1. 用户点击地图省份。
2. `CountyInteractionIndex` 将内部省份或 `baronyId` 映射为稳定 `countyId`。
3. MapUiStore 写入 `{ countyId, locationId: null }`。
4. MapDrawer 按 `countyId` 投影政治、人物、资产和地点列表。
5. MapCanvas 仅同步该伯爵领的内部地点和受限动态图层。
6. 用户点击具体地点时写入同一 county 下的 `locationId`。
7. 用户点击“前往这里”时详情组件把 county 或 location 解析为稳定目标地点并请求路线。
8. 路线确认后进入统一世界事务队列；地图不直接修改人物位置。
9. 成功回合结算后，人物地点、资产地点、时间线和地图投影从统一世界状态重新读取。

## 14. 故障隔离

- semantic membership 加载失败：保留基础地形，禁用伯爵领选择并显示明确重载提示；不得退回男爵领点选。
- 政治投影失败：隐藏政治填色，仍允许伯爵领和地点浏览。
- 人物或资产投影失败：对应图层和列表显示暂不可用，不影响另一类信息。
- 地点图标加载失败：伯爵领面板地点列表仍可操作。
- 路线系统失败：只影响路线预览，不影响地图浏览和世界状态。
- 三维地形失败：回退二维表面，保持相同选择语义。
- 地图错误继续由 MapErrorBoundary 隔离，正文、人物卷宗和回合提交不受影响。

## 15. 性能约束

1. 远景不构造人物和资产 GeoJSON。
2. 未选中伯爵领时不加载动态人物和资产位置详情。
3. 选中伯爵领后按 county membership 先限域，再聚合和写入 MapLibre source。
4. 缩放连续过程中只更新样式表达式；只有跨越语义阈值、选择变化或视野停止时才重建动态数据。
5. 图层偏好单独更新相关 source/layer，不重新应用整套地图模式。
6. 政治 feature-state 继续只更新受影响头衔。
7. 外部定位和内部点击必须区分；内部选择不得触发不必要的 flyTo。
8. 地图抽屉关闭时继续销毁 MapLibre 实例和 worker 监听。
9. 不新增网络地图依赖。

## 16. 可访问性与反馈

- 所有工具栏按钮有文字、可见焦点和 `aria-pressed` 或复选状态。
- “正在选择旅行目的地”必须有常驻文字反馈和同位置取消按钮。
- 地图信息开关不能只靠颜色表示状态。
- 聚合标记提供可读类别和数量，例如“临冬城，已知人物 6”。
- 键盘用户可以通过搜索和详情列表完成选择伯爵领、地点、人物、资产和旅行目标。
- 不使用 Emoji。

## 17. 测试策略

### 17.1 纯逻辑测试

- 任意省份直接解析到伯爵领，不产生 realm、kingdom、duchy 展开状态。
- location 与 county 选择不变量。
- county 旅行目标稳定解析为主要地点。
- 外部 location focus 正确解析父伯爵领。
- 缩放阈值返回远景政治、中景伯爵领和近景内部地点表达。
- 人物资产按选中 county 限域、按地点聚合并遵守预算。
- 情报级别、死亡和未知位置过滤不回归。

### 17.2 UI 结构审计

- 工具栏不存在五模式标签。
- 工具栏只暴露搜索、地图信息、俯视和归北。
- 地图信息开关相互独立。
- 伯爵领和地点分别使用独立详情组件。
- 旅行改点状态有可见提示和取消入口。
- 人物、资产和地点点击不会穿透到伯爵领层。

### 17.3 集成测试

- 点击临冬城所在区域一次即可打开对应伯爵领面板。
- 点击选中伯爵领内部的临冬城图标打开具体地点详情。
- 从正文点击君临，地图选中父伯爵领和君临地点。
- 从人物卷宗点击所在地执行相同定位。
- 人物与资产只在选中伯爵领内出现，清除选择后消失。
- 发起、改点、确认和取消旅行保持统一世界事务队列语义。
- 已有旅程在查看政治、人物和资产时仍持续显示。
- 返回人物或资产抽屉后地图视野和选择保持不变。

### 17.4 性能测试

- 远景动态人物和资产 source 为空。
- 连续滚轮缩放不在每帧重建动态 GeoJSON。
- 选择单一伯爵领不会扫描或序列化全大陆人物与资产点。
- 切换单个图层不会重新创建地图实例或重新加载静态瓦片。

## 18. 验收标准

1. 地图界面不再出现五种模式。
2. 玩家无需切换任何模式即可点击并选中伯爵领。
3. 从任意政治层级画面点击一次都能得到伯爵领结果。
4. 远景没有人物和资产点；未选择伯爵领时也没有动态图标。
5. 近景只展开当前伯爵领内部地点。
6. 伯爵领与具体地点在状态和 UI 中清晰分开。
7. 人物和资产即使开启也不会显示选中伯爵领以外的内容。
8. 旅行只能从详情发起，规划状态可见、可修改、可取消。
9. 已有旅程不会因为浏览其他地图信息而消失。
10. 正文、人物卷宗和资产位置跳转统一选中正确父伯爵领与地点。
11. 地图失败不会阻断正文、人物卷宗和回合结算。
12. 相关测试、TypeScript 检查和 Windows 代码构建通过。

# CK3 式五级头衔地图设计

日期：2026-08-20
状态：已实现；当前运行时权威说明见 `docs/CURRENT_ARCHITECTURE.md`

## 1. 背景与问题

当前地图的可见语义层只有 `realm → duchy → county`。其中 `realm` 实际是“北境、河间地、多恩”等地理战略区域，不是完整的 CK3 头衔等级；王国头衔被折叠进政治投影，霸权和帝国头衔没有成为可见地图层级。地图又额外生成“史塔克家族”“兰尼斯特家族”“拜拉席恩家族”等政治家族副标题，导致同一家族持有多个同级头衔时出现重复文字。

CK3 的地图身份应由头衔决定。家族属于持有人资料，不应作为第二套地名覆盖地图。本设计把可见行政语义改为 `霸权 → 帝国 → 王国 → 公国 → 伯爵领`，彻底删除地图家族副标题，同时继续以伯爵领作为玩家的最小政治交互单位。

本设计取代以下旧规则：

- `2026-08-19-ck3-semantic-map-zoom-design.md` 中的三级可见语义层和政治家族副标题。
- `2026-08-20-unified-county-map-interaction-design.md` 中仅涉及三级标签表达的部分。

统一地图、伯爵领主交互、地点详情、旅行、人物与资产限域等其余规则保持不变。

## 2. 目标

1. 地图只显示头衔名称，不显示任何独立家族名称副标题。
2. 可见头衔层级扩展为霸权、帝国、王国、公国和伯爵领五级。
3. 缩放时只显示一个主要头衔层级，采用明确阈值硬切换，不混合多级文字。
4. 远景显示政治结构，近景让政治填色退出并恢复地形；伯爵领仍是最小政治交互单位。
5. 使用 AGOT 已安装模组的头衔层级、中文本地化和头衔颜色离线生成项目数据；运行时不读取模组目录。
6. 当前持有人、实际控制者、家族和家徽只进入伯爵领详情中的政治资料，不作为地图地名。
7. 继续不生成男爵领可见边界、标签或地图交互层。
8. 测试版直接升级生成数据格式，不兼容旧语义地图数据。

## 3. 非目标

1. 不恢复五种地图模式。
2. 不恢复男爵领地图层级或男爵领圆点。
3. 不在地图表面同时显示头衔名、持有人名和家族名。
4. 不实现战争、军队、补给、建设或完整封臣契约系统。
5. 不让 LLM 接收 `h_`、`e_`、`k_`、`d_`、`c_` 等内部键。
6. 不允许运行时访问 Steam、Workshop、网络地图服务或本机模组文件。

## 4. 头衔层级与玩家可见名称

可见层级按 AGOT/CK3 头衔前缀定义：

| 内部等级 | 前缀 | 玩家语义 | 示例 |
|---|---|---|---|
| `hegemon` | `h_` | 霸权头衔 | 铁王座 |
| `empire` | `e_` | 帝国级头衔 | 北境、谷地、多恩 |
| `kingdom` | `k_` | 王国级头衔 | 临冬城王国等 AGOT 实际头衔 |
| `duchy` | `d_` | 公国级头衔 | 临冬城公国、龙石岛公国 |
| `county` | `c_` | 伯爵领 | 临冬城伯爵领、君临伯爵领 |

“霸权、帝国、王国、公国、伯爵领”是系统等级，不强制拼接到地图文字。地图显示 AGOT 中文本地化中的正式头衔名称，避免出现“北境帝国”一类不符合世界观的机械文本。详情面板可以另行显示等级。

`baronyId` 继续作为地点、省份和旅行节点的内部稳定映射键，不成为 `SemanticRank`。

## 5. 离线数据模型

### 5.1 完整头衔祖先链

地图导入器的 `TitleAncestors` 扩展为：

- `hegemon_id?: string`
- `empire_id?: string`
- `kingdom_id?: string`
- `duchy_id?: string`
- `county_id?: string`

`parse_title_hierarchy` 在递归读取 AGOT `common/landed_titles` 时保存 `e_ → k_ → d_ → c_ → b_` 的法理祖先链。AGOT 的 `h_the_iron_throne` 是特殊霸权头衔，并不直接包裹全部 `e_` 定义，因此其可见覆盖范围不得靠前缀或文件顺序猜测。

### 5.2 霸权覆盖范围

首版在地图导入覆盖配置中显式声明 `h_the_iron_throne` 的组成帝国级头衔或战略区域。覆盖范围只包含铁王座统治语义下的七国，不自动吞并塞外或绝境长城。该配置使用稳定头衔 ID，并由导入审计验证：

- 引用的帝国级头衔存在；
- 组成范围无重复省份；
- 霸权几何非空且在地图边界内；
- 未配置的 `h_` 不生成虚假世界范围几何。

后续若世界状态支持正式独立或臣服变化，可以在运行时政治投影中改变霸权归属；本轮只建立可靠的 298 年开局语义，不凭叙事文本推断臣服。

### 5.3 语义数据

`SemanticRank` 改为：

```ts
type SemanticRank = 'hegemon' | 'empire' | 'kingdom' | 'duchy' | 'county'
```

每个可见 `SemanticTitle` 至少包含：

- 稳定 `featureId`
- `titleId`
- `rank`
- 中文 `name`
- `mapX`、`mapY`
- `importance`
- `regionId`
- `titleColor`

地点成员映射改为：

- `locationId`
- `baronyId`
- `countyId`
- `duchyId`
- `kingdomId`
- `empireId`
- 可选 `hegemonId`
- `regionId`

旧 `realmId` 不再同时承担“地理战略区域”和“最高政治头衔”两种含义。地理归属统一放在 `regionId`，政治头衔使用明确的五级 ID。

### 5.4 头衔颜色

政治色使用 AGOT landed title 的 `color`，而不是持有人家族颜色：

1. 导入 `{ r g b }` 并转换为合法十六进制色。
2. 对过亮、过饱和颜色只做统一的显示端压暗和降饱和，不改原始导入值。
3. 缺少合法颜色时按稳定 `titleId` 生成低饱和回退色。
4. 持有人或家族变化不改变头衔自身颜色。
5. 军事占领继续使用争议边界表达，不用第二块家族色覆盖法理头衔色。

## 6. 生成物与瓦片结构

语义矢量瓦片为五组政治颜色面、五组真实边界线和一组标签语义。颜色面与边界线必须分层，禁止用经瓦片裁切的多边形直接充当描边几何，以免把瓦片切口绘成十字接缝：

- `hegemon_surfaces` / `hegemon_boundaries`
- `empire_surfaces` / `empire_boundaries`
- `kingdom_surfaces` / `kingdom_boundaries`
- `duchy_surfaces` / `duchy_boundaries`
- `county_surfaces` / `county_boundaries`
- `title_labels`，通过 `rank` 区分五级标签

仍输出：

- `/assets/agot-map/semantic/{z}/{x}/{y}.pbf`
- `/data/agot-map/semantic/titles.json`
- `/data/agot-map/semantic/membership.json`

导入器为每一级合并其下属省份几何并使用 `representative_point` 计算位于领地内部的标签锚点。缺少中文本地化的头衔保留边界和颜色，但不生成英文可见标签，并写入导入审计报告。

地图 schema 版本提升。旧三级语义数据必须被明确拒绝，不能在运行时静默降级成混合层级。

## 7. CK3 式缩放表达

首版采用以下硬切换阈值：

| Zoom | 主要层级 | 表达 |
|---|---|---|
| `0.00–0.84` | 霸权 | 铁王座等最高政治范围、最高级边界和头衔名 |
| `0.85–1.54` | 帝国 | 北境、谷地、多恩等帝国级头衔 |
| `1.55–2.24` | 王国 | 王国级头衔与边界 |
| `2.25–2.94` | 公国 | 公国级头衔与边界 |
| `2.95–4.59` | 伯爵领 | 伯爵领名称与边界，地图主要政治交互阶段 |
| `4.60–6.00` | 伯爵领与地点 | 保留伯爵领边界，选中伯爵领才展开内部地点；政治面填色退出 |

规则：

- 同一时刻只显示一个主要头衔等级的普通标签和普通边界。
- 非当前等级标签必须在 `layout.visibility` 层关闭；仅将文字透明度设为 0 不合格，因为透明符号仍会参与碰撞并挤掉当前等级名称。
- 霸权、帝国、王国和公国标签不得因同级符号碰撞被淘汰；这些等级数量有限，允许密集区域出现少量文字重叠。伯爵领继续使用碰撞避让。
- 过阈值后直接切换，不做多层文字交叉淡入。
- 政治填色按同一等级的 `titleColor` 切换。
- Zoom `4.60` 后普通政治填色为 0，地形贴图成为主体。
- 选中伯爵领的金色描边、旅行路线、争议边界和当前位置不受普通层级切换影响。
- 地图内部缩放不改变选择状态，也不自动打开详情。

## 8. 地图文字与详情职责

### 8.1 地图表面

地图只显示：

- 当前缩放等级的头衔名称；
- 必要的地点名称；
- 旅行和当前选择相关文字。

地图不再显示：

- `史塔克家族`、`兰尼斯特家族`、`拜拉席恩家族`等家族副标题；
- 头衔持有人姓名；
- 家徽名称或重复政治说明。

删除 `POLITICAL_HOUSE_LABEL_SOURCE`、`POLITICAL_HOUSE_LABEL_LAYER`、对应 GeoJSON 聚合和同步逻辑。不能只是把图层设为隐藏后继续维护第二套家族标注数据。

### 8.2 详情面板

伯爵领详情中的政治资料负责显示：

- 头衔正式名称和等级；
- 当前公开持有人；
- 持有人家族与家徽；
- 法理上级头衔链；
- 实际控制者与争议状态。

家族仍是游戏世界资料，但不再承担地图地名职责。

## 9. 交互与系统联动

1. 点击任意可见政治区域仍最终解析到伯爵领，保持伯爵领主交互合同。
2. 远景点击霸权、帝国、王国或公国区域时，只用于视觉选区或定位；真正打开的详情仍以点击位置对应伯爵领为主，不恢复逐级下钻。
3. 地点搜索与正文地点链接继续解析父伯爵领。
4. 人物所在地、资产所在地、旅行路线和统一时间线不因语义等级增加而改变权威 ID。
5. LLM 地点上下文继续输出具体地点、伯爵领、公国和更高中文头衔名，但不输出内部键或家族标签。
6. 伯爵领内部地点目录继续保持一地点一行，不增加头衔等级说明。

## 10. 性能边界

1. 五级边界离线生成并切入本地矢量瓦片，不在浏览器中合并省份几何。
2. MapLibre 图层可以预先定义，但只有当前主要等级可见。
3. 缩放只切换已有图层 visibility/表达式，不重建政治、人物或资产 GeoJSON。
4. 删除家族副标题同步后，平移和缩放不再重新计算家族标签集合。
5. `titles.json` 和 `membership.json` 可以增加字段，但首屏仍按现有轻量索引加载，不读取全部地点详情。

## 11. 错误处理

- 缺少必需的伯爵领或公国祖先：导入失败。
- 王国或帝国祖先缺失：允许该省份跳过对应等级，但不得伪造 ID；该等级不混入更低级标签，只保留地形或稳定区域底色。
- 霸权覆盖未配置：不生成该霸权几何，不把整张地图错误染成同一颜色。
- 头衔颜色非法：使用稳定低饱和回退色并记录审计项。
- 中文本地化缺失：保留边界，隐藏该条英文标签并记录审计项。
- 五级语义资料运行时载入失败：只隔离地图子树，正文和人物卷宗继续可用。

## 12. 测试与验收

### 12.1 导入器

- 解析 `h/e/k/d/c/b` 完整祖先链。
- 正确生成五级几何、标题和成员映射。
- `h_the_iron_throne` 只覆盖显式配置范围。
- 头衔颜色解析、回退和确定性输出。
- 缺失祖先、重复省份、越界几何和非法颜色审计。
- 两次导入输出哈希一致。

### 12.2 运行时

- `SemanticRank`、schema、repository 正确读取五级数据。
- 每个缩放阈值前后只显示一个主要头衔等级。
- 政治填色使用当前等级的头衔颜色并在近景退出。
- 地图运行时代码不存在家族副标题 source、layer 或同步逻辑。
- 点击区域仍解析到正确伯爵领。
- 搜索、正文地点跳转、人物与资产位置、旅行和时间线回归通过。
- 连续缩放不重建动态 GeoJSON。

### 12.3 生成数据审计

- 五级可见头衔数量均大于 0，其中霸权至少包含铁王座。
- 每个可见伯爵领有公国祖先。
- 有王国、帝国或霸权祖先的地点映射一致。
- 所有可见标签均为中文。
- 地图家族副标题数量恒为 0。

### 12.4 构建

- `npm run test:agot-map-import`
- 新增五级语义缩放与 schema 测试
- `npm run verify:map`
- 正文、人物、资产、旅行与世界上下文联动测试
- `npx tsc --noEmit`
- Windows `npm run build:code`
- `git diff --check`

## 13. 完成定义

满足以下条件才算完成：

1. 地图不再生成或显示任何家族名称副标题。
2. 霸权、帝国、王国、公国和伯爵领五级均来自 AGOT 头衔数据。
3. 五级边界、标签、颜色和成员关系已经离线生成到项目中。
4. 缩放按本设计阈值硬切换，近景恢复地形主体。
5. 伯爵领仍是最小政治交互单位，男爵领没有重新出现。
6. 现有人物、地点、资产、旅行和时间线联动通过回归验证。
7. 不读取远程或运行时模组资源，不包含 Emoji。

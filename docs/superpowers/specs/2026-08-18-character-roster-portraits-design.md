# 精简人物名单与离线 Wiki 头像系统设计

## 背景

当前运行时人物数据集包含 126,978 条记录，其中 99,284 条属于远祖家谱，21,148 条属于 AGOT 辅助人物。298 年实际在世人物只有 15,391 名。完整家谱既增加运行时数据体积，也让搜索、开局选择与头像匹配被大量不会参与当前游戏的人物占据。

人物窗口目前只有统一的 SVG 浮雕占位图。项目没有人物头像字段、头像资源库或来源记录。目标是在不牺牲现任领主和核心亲属关系的前提下裁剪人物数据，并为能够可靠对应到 AWOIAF Wiki 人物条目的角色离线导入原著风格插画。

## 已确认目标

1. 只保留 298 年在世的正典与半正典人物、298 年现任头衔持有人，以及这些人物的一层亲属。
2. 一层亲属包含父母、配偶、子女和兄弟姐妹，不从保留的已故亲属继续递归扩展。
3. AGOT 辅助人物只有在担任现任头衔持有人或属于保留人物的一层亲属时才保留。
4. 亲属必须在 298 年已经出生；未来人物不进入当前名单。
5. 使用 AWOIAF Wiki 人物条目的原著插画，不使用运行时热链。
6. 只有唯一、高置信的匹配才采用头像；同名或证据不足时宁可保留占位图。
7. 图片保存到项目本地，并记录页面、原图、作者、说明与授权元数据。
8. 不兼顾测试版旧存档兼容性。
9. 运行时不读取 CK3、AGOT 模组或 Wiki 网络数据。

## 人物名单裁剪

### 种子人物

从完整投影后的 298 年人物集合建立种子集合：

- `born === true && alive === true && canonTier in {canon, semicanon}`；
- 298 年 `title-holders.json` 中仍在世且已经出生的持有人，不限正典等级。

### 一层扩展

以完整、尚未裁剪的亲属索引为依据，对每个种子人物加入：

- 父亲；
- 母亲；
- 配偶；
- 子女；
- 兄弟姐妹。

被加入者必须存在于完整人物集合且 `born === true`。扩展只执行一次，不以新增亲属作为下一轮种子。

按当前数据估算，运行时人物数量将从 126,978 降至约 11,500。最终数量以确定性构建结果为准，并写入报告。

### 裁剪后的引用处理

生成最终数据集时：

- `fatherId`、`motherId` 指向已删除人物时清空；
- `spouseIds`、显式关系与反向亲属数组只保留仍存在的 ID；
- `title-holders.json`、装束分片和其他人物映射只保留最终名单人物；
- 重新生成搜索索引、人物分片、亲属分片、统计报告和数据哈希；
- 数据审计禁止任何悬空人物引用。

### 生成器一致性

名单选择规则放在独立、纯函数化的 Python 模块中，由两条路径共用：

1. 正常人物导入器在完整历史投影后、写出运行时数据前应用；
2. 一次性或重复可运行的项目内裁剪命令读取现有打包数据并应用同一规则。

这样当前项目无需重新读取本地 AGOT 游戏文件，未来如重新离线导入人物也不会恢复被删除的远祖和孤立辅助人物。

## 头像数据源

### Wiki 目录

头像导入器使用 AWOIAF 的 MediaWiki API，优先枚举人物分类中的条目并读取：

- 页面标题与规范 URL；
- `Infobox character` 中的姓名、姓氏、别名、家族、出生年份和父母；
- 主图文件名与图片说明；
- 图片原始 URL、尺寸、MIME、作者、授权名称、授权 URL 和说明页 URL。

网络访问只发生在显式离线导入命令中。API 请求使用明确的 User-Agent、限速、重试和本地缓存，不在测试与游戏运行时发送请求。

### 图片筛选

只接受人物信息框中的人物插画。以下图片自动拒绝或进入人工审计：

- 家徽；
- 地图、地点或建筑；
- 武器、王冠及其他物品；
- 电视剧演员照片或剧集截图；
- 尺寸过小、损坏或非图片资源；
- 页面没有人物信息框或主图。

允许原著相关的书籍插画、卡牌插画及 Wiki 人物艺术图，但必须保留原说明和来源元数据。

## 人物匹配

### 匹配证据

项目人物与 Wiki 人物页的匹配使用多项证据评分：

- 规范化后的英文名完全一致；
- Wiki 姓氏与人物家族或私生子姓氏一致；
- 出生年份或年代相容；
- 父母姓名相容；
- 别名与项目人物名称相容；
- Wiki 分类中的家族信息相容。

仅名字相同不能构成自动匹配。家族冲突、年代明显冲突或父母冲突会直接拒绝候选。

### 唯一性和阈值

自动匹配必须同时满足：

- 得分达到高置信阈值；
- 第一候选明显高于第二候选；
- 同一 Wiki 页面未被另一个游戏人物占用；
- 不存在硬冲突。

同名人物、同一家族重复名字和历史祖先进入歧义报告，不进行猜测。

### 人工覆盖

维护一个小型、可审计的覆盖文件，键为稳定 `CharacterId`，值为 Wiki 页面标题。覆盖用于：

- 琼恩·雪诺等姓名与家族规则不足的著名人物；
- Wiki 页面标题使用绰号或特殊拼写的人物；
- 自动匹配明确失败但可以人工确认的人物。

覆盖同样必须通过页面存在、人物信息框、图片类型与资源完整性校验。

## 图片处理与文件结构

图片下载后转换为 WebP，限制最大尺寸并保留适合人物框的纵横比。默认使用顶部偏中的视觉焦点；人工覆盖可以为少量构图特殊的图片设置焦点。

建议目录：

```text
public/assets/character-portraits/
  <stable-file-name>.webp
public/data/agot-character-portraits/
  manifest.json
  attribution.json
  shards/<character-shard>.json
  reports/import-report.json
  reports/ambiguous.json
  reports/unmatched.json
```

头像映射与主人物数据分离。人物重新导入不会删除已下载头像，也不会要求在每个人物记录中复制完整来源元数据。

头像引用类型：

```ts
interface CharacterPortraitRef {
  characterId: CharacterId;
  assetPath: string;
  attributionId: string;
  focalPoint?: string;
}
```

归因记录包含页面 URL、页面标题、原图 URL、图片说明页、作者、说明、授权名称和授权 URL。缺失的上游元数据保留为空，不伪造作者或授权。

## 运行时架构

新增只读头像仓储，按人物分片加载头像映射并缓存请求。它只读取项目中的 JSON 和本地 WebP。

提供统一的 `CharacterPortrait` 组件，输入稳定人物 ID、家族图标和尺寸变体：

- 有本地头像时显示图片；
- 没有映射时显示现有家徽背景与浮雕剪影；
- 图片加载失败时立即切换到相同回退；
- 大头像优先加载，小卡片头像使用懒加载；
- 焦点由映射控制，默认顶部偏中。

统一组件用于：

- CK3 人物卷宗主头像；
- 配偶、父母、子女与兄弟姐妹卡片；
- 人物搜索结果；
- 开局现成人物选择；
- 推荐人物卡片；
- 其他以稳定人物 ID 展示的小型人物卡。

自建人物没有稳定 AGOT ID 时继续使用浮雕剪影或既有自建头像逻辑。

## 报告和失败处理

导入过程生成以下统计：

- 运行时保留人物数及各正典等级数量；
- 自动匹配数；
- 人工覆盖数；
- 有条目但无可用图片数；
- 无 Wiki 条目数；
- 同名歧义数；
- 被图片类型规则拒绝数；
- 下载或转换失败数。

单张图片失败不终止整个导入，但写入失败报告。数据结构错误、覆盖指向不存在页面、一个 Wiki 页面被重复绑定或输出包含悬空文件时构建失败。

## 测试与验收

### 人物裁剪

- 正典和半正典在世人物全部保留；
- 现任辅助领主全部保留；
- 上述人物的一层亲属保留；
- 已故亲属的祖先不会继续递归保留；
- 孤立、无头衔辅助人物被删除；
- 未来人物被删除；
- 所有亲属、头衔与装束引用可解析；
- 输出与输入顺序无关且重复运行字节稳定。

### 头像匹配

- 英文名、家族、年代和父母一致时可以匹配；
- 仅同名时拒绝；
- 家族或年代冲突时拒绝；
- 第一、第二候选差距不足时拒绝；
- 人工覆盖稳定生效；
- 同一 Wiki 页面不能自动分配给多个人；
- 测试使用本地 API 固件，不依赖网络。

### 资源与界面

- 每条头像映射对应真实 WebP；
- 每个归因 ID 存在；
- 不存在未引用的下载图片；
- 头像加载失败时显示回退；
- 人物卷宗、关系卡、搜索和开局人物选择使用统一组件；
- 完整 `npm run verify` 与生产构建在断网环境下通过。

## 非目标

- 不为没有 Wiki 图片的人物生成 AI 头像；
- 不从 CK3 或 AGOT 的 3D DNA 在运行时渲染头像；
- 不采用电视剧演员剧照；
- 不使用低置信匹配提高表面覆盖率；
- 不保留完整远祖家谱供运行时搜索；
- 不处理测试版旧存档兼容迁移。

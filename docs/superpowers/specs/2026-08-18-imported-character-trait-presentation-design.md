# 导入人物特质呈现设计

## 目标

AGOT 离线人物数据保留原始特质 ID，但任何人物卷宗、开局人物卡与玩家角色栏都不得把未翻译的机器 ID 直接显示给玩家。导入特质统一分为正式显示、隐藏辅助修正、未成年限定和身份/状态四类。

## 数据边界

原始人物分片仍是离线构建产物，运行时只读取项目内 JSON，不读取 CK3 或 AGOT 安装目录。`ResolvedCharacter.traits` 继续保存完整原始 ID，呈现层通过统一策略投影。现成人物转为玩家时额外保存原始导入 ID，显示与规则使用经过策略筛选的正式 ID。

## 分类规则

- `display`：性格、生活方式、先天、健康、教育和名声等常规可见特质。每个可见 ID 必须有中文名称、角色扮演描述、现有游戏图标、分类和基础修正。
- `hidden_modifier`：仅供属性或规则层使用的辅助修正，不进入人物特质栏。包括勇武教育附加等级、共和国知识等级、技术占位 ID。
- `childhood_only`：`rowdy`、`bossy`、`charming`、`pensive`、`curious` 只在人物未满 16 岁时显示；成年后不显示，但原始数据不删除。
- `status`：骑士、学士、守夜人、教士、寡居、拒婚等身份或阶段状态。它们仍显示在人物特质栏，但策略结果单独列出，便于后续拆分独立状态区域。

若原始 ID 与已有正式定义完全等价，策略可使用 `replacementId` 归一化，避免重复定义。输出必须去重，并由既有显示排序保证教育特质在第一位。

## 接入点

1. `src/data/importedCharacterTraitPolicy.ts` 提供分类表和 `filterImportedCharacterTraits()`。
2. `src/data/importedCharacterTraitDefinitions.ts` 提供开局存活人物中尚缺的中文可见定义。
3. `createNpcDossier()` 根据人物当前年龄投影可见特质，并保留隐藏和状态 ID。
4. `createLordFromExistingCharacter()` 使用相同投影，玩家 `traitIds` 只含正式可见 ID，`importedTraitIds` 保存完整原始数据。
5. 开局人物卡与人物卷宗沿用正式定义解析，不再出现英文机器 ID。

## 审计与验证

新增离线审计，扫描开局时已出生且存活的全部人物。每个原始特质必须满足以下之一：存在正式定义，或在策略中被明确归为隐藏/年龄限定/状态并能解析到正式定义。审计同时禁止可见结果缺少定义、中文名称或实际存在的图标文件。

聚焦测试覆盖：成年/儿童年龄门槛、隐藏辅助修正、状态输出、去重、NPC 卷宗、现成人物转玩家和全量数据覆盖。最后运行特质检查、人物测试、类型检查、构建与完整 `verify`。

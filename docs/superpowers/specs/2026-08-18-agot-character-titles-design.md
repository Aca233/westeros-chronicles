# AGOT 人物初始头衔设计

## 目标

让人物卷宗在 298 AC 开局时显示角色实际持有的 AGOT 领地头衔。数据只来自 Steam 创意工坊项目 `2962333032` 的 AGOT 模组，不能读取 CK3 原版文件；没有领地的人物明确显示“未持有封地”，不根据家族、剧情身份或继承顺位虚构爵位。

## 数据边界与时间投影

- 人物继续来自 `history/characters/*.txt`，头衔持有史只来自同一 AGOT 模组的 `history/titles/*.txt`。
- 导入日期为 `8298.1.1`。每个头衔只应用不晚于该日期的日期块，并以日期及源码顺序最后一次直接 `holder = ...` 为准。
- `holder = 0` 表示该头衔在开局时没有持有人。
- 只读取日期块顶层的 `holder`，不执行 `effect`、`if`、作用域切换或其他 Paradox 脚本，因此导入结果可重复且不会推测脚本效果。
- 头衔文件、AGOT 简体中文本地化和模组描述文件全部进入来源校验和；来源清单记录头衔文件数量。

## 头衔解析与显示规则

新增 `scripts/agot_character_import/titles.py`，把头衔历史投影成 `角色原始 ID -> 头衔条目列表`。条目包含内部头衔 ID、本地化名称和层级。层级优先级固定为：

1. `h_` 特殊最高头衔
2. `e_` 帝国级
3. `k_` 王国级
4. `d_` 公国级
5. `c_` 伯爵领级
6. `b_` 男爵领级
7. 其他未知前缀

同一角色持有多个本地化后同名的领地时，只保留优先级最高的条目；同层级则按头衔 ID 稳定排序。人物卷宗使用排序后的第一项作为主头衔。名称优先使用 AGOT 简体中文本地化；缺失本地化时把前缀和下划线组成的内部 ID 转成可读英文名称，绝不直接展示内部 ID。

## 生成数据

为避免重写和膨胀全部人物分片，生成独立文件：

```text
public/data/agot-characters/title-holders.json
```

格式为：

```json
{
  "agot:Stark_3": [
    { "id": "e_the_north", "name": "北境", "tier": "empire" },
    { "id": "k_winterfell", "name": "临冬城", "tier": "kingdom" }
  ]
}
```

数据集 schema 升至 2。`manifest.json` 的计数增加 `titleHolderCount` 与 `heldTitleCount`，数据集哈希纳入完整头衔映射，保证头衔历史或本地化发生变化时版本随之改变。

## 运行时合并与事件叠加

`StaticCharacterRepository` 延迟并只加载一次 `title-holders.json`。人物分片读取完成后，`get()` 将对应条目合并为：

- `titleIds`: 排序后的内部 ID，供动态剥夺事件精确匹配；
- `titles`: 与之同序的本地化显示名称，供人物卷宗展示。

`projectCharacterEvents()` 从这两组初始值开始投影：

- `GRANT_TITLE` 追加动态头衔；
- `REVOKE_TITLE` 优先按内部 ID 删除对应 ID 与显示名称，也允许删除动态事件直接使用的显示字符串。

这样存档中的授予、剥夺仍叠加在 AGOT 开局状态上，而不是替换静态数据。当前为测试版，不为 schema 1 数据或旧存档增加兼容分支。

## 空状态与错误处理

- 有实际领地：显示最高层级、本地化后的主头衔，并保留去重后的完整头衔列表。
- 无实际领地：显示“未持有封地”。丹妮莉丝、乔佛里、瑟曦、詹姆、提利昂、罗柏、琼恩·雪诺、珊莎和艾莉亚等角色不会仅因身份显赫而获得虚构领地。
- 头衔映射格式无效或读取失败：人物仓库读取失败并沿用现有人物加载错误流程，不静默制造空头衔。

## 验证

- Python 测试覆盖日期截止、未来事件忽略、`holder = 0`、同日源码顺序、嵌套脚本忽略、中文本地化、层级排序、同名去重和确定性输出。
- 前端测试覆盖 schema 2、头衔映射只加载一次、静态人物合并、动态授予与剥夺、主头衔及“未持有封地”空状态。
- 数据集检查确认映射文件、计数、AGOT-only 来源，以及劳勃、艾德、琼恩·艾林等关键角色在 298 AC 的已知头衔。
- 最终运行导入器、针对性测试、生产构建和 `npm run verify`。

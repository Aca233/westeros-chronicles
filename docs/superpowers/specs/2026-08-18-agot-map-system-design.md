# AGOT 混合地图与旅行系统设计

**日期：** 2026-08-18

**状态：** 用户已确认设计内容，等待进入实施计划

**项目根目录：** `/mnt/c/agot`

## 1. 目标

在现有维斯特洛编年史项目中建立一套与正文、人物、物品、时间线和世界历史共用权威状态的地图系统。

第一版覆盖完整维斯特洛，包括七国、塞外、长城、铁群岛、龙石岛和近海航线。远景表现地区与政治势力，近景表现全部有名称的城堡、城市、村庄、港口、遗迹、道路和旅行路线。

地图不是独立展示页。它从第一版起必须支持地点查询、路线规划、短途结算、长途多回合旅行、人物与车辆移动、地点资产访问、动态政治投影和知识可见性过滤。

第一版采用二维平面视图，但构建产物、坐标协议和渲染引擎必须直接兼容后续三维地形，不允许三维阶段推翻地点、路线或政治边界数据。

## 2. 非目标

第一版不实现：

- 厄斯索斯、索斯罗斯、乌尔特斯和其余已知世界的可浏览内容。
- 宣战、征服、围城、封地建设和领地经济管理。
- 实时三维倾斜视角和城堡三维模型。
- 对 CK3 或 AGOT 安装目录的运行时访问。
- 旧测试存档中的自由文本地点迁移。
- 依靠 D20 决定普通赶路是否成功。
- 上帝视角式的秘密人物、隐藏资产和未知事件展示。

数据格式保留扩展整个已知世界、三维地形和领地操作的能力，但这些功能不进入第一版验收范围。

## 3. 已确认的产品决策

### 3.1 地图形态

采用混合地图：

- 远景显示地区、政治势力、主要边界和首府。
- 中景显示公国、伯爵领、主要道路与重要城堡。
- 近景显示全部命名地点、普通道路、港口、据点和路线细节。

### 3.2 首版地理范围

第一版只生成完整维斯特洛范围。所有地点保留原始 9216×6144 地图像素坐标，因此未来增加厄斯索斯时不改变既有 ID、坐标或旅行图。

### 3.3 地图入口

地图从主界面左侧打开，与右侧人物卷宗镜像：

- 关闭时显示左缘竖向“维斯特洛地图”标签。
- 点击后从左侧滑出宽地图抽屉。
- 桌面端宽度约 `72vw`，最大 `1180px`。
- 小屏笔记本约 `82vw`，移动端占满屏幕。
- 点击遮罩、再次点击标签或按 `Esc` 收起。
- `M` 为地图快捷键。
- 地图与人物卷宗互斥，打开一个时自动收起另一个。

### 3.4 旅行方式

- 同一城堡内部或附近地点可在下一次成功对话后抵达。
- 同一地区短途旅行在一个成功回合内推进对应日期并抵达。
- 跨地区长途旅行建立持续旅程状态，按多回合推进。
- 长途旅行允许暂停、停留、改道、返回和事件中断。
- 路线提供最快、最安全和最省钱三种策略，并允许添加途经地点。
- 普通赶路不投 D20；只有渡河、逃亡、突破封锁等确实不确定的行动进行检定。

### 3.5 地图知识

基础地理始终可见，动态情报受人物知识限制。情报分为已确认、传闻、过时和未知四级。地图不能泄露秘密人物、隐藏资产、未公开死亡和玩家不应知道的事件。

## 5. 离线构建架构

新增独立 Python 包 `scripts/agot_map_import/`，按以下阶段处理：

1. 验证模组源身份、必需文件、图像尺寸和地图定义。
2. 解析省份颜色、ID、男爵领名称、特殊水域与不可通行区域。
3. 解析维斯特洛地理区域及其递归成员。
4. 解析王国、公国、伯爵领和男爵领层级。
5. 解析中文本地化、298 年省份状态和头衔基础持有人。
6. 从省份位图计算省份边界、质心、包围框和实际相邻关系。
7. 合并 `adjacencies.csv` 的渡口、河流和海路连接。
8. 从道路遮罩、地形、河流和海域生成加权旅行图。
9. 生成维斯特洛裁剪范围的二维地形瓦片。
10. 生成省份、边界、道路、航线、地点和标签矢量瓦片。
11. 将 16 位高度图转换为 MapLibre 可读取的 Terrain-RGB 或 Terrarium DEM 瓦片。
12. 写入清单、分片、来源信息和审计报告，并原子替换旧生成目录。

真实 9216×6144 地图导入不加入普通 `npm run verify`。普通测试使用小型 fixture；真实生成结果由独立数据审计命令验证。

## 7. 渲染架构与三维兼容

地图渲染使用 MapLibre GL JS，不使用单张巨图、数千 DOM 标记或全地图 SVG。

### 7.1 第一版二维渲染

- 本地 XYZ WebP 地形瓦片作为底图。
- 本地矢量瓦片承载省份、政治边界、道路、航线、河流、地点和标签。
- DEM 第一版只用于山体阴影。
- 视角锁定为平面俯视，不开放倾斜和旋转。
- 图标按缩放级别显示或聚合。

### 7.2 坐标协议

游戏逻辑保存 AGOT 原始像素坐标 `mapX`、`mapY`。MapLibre 渲染层使用稳定函数将像素坐标映射到内部投影。旅行距离、相邻关系和路线代价不能使用伪造的现实经纬度计算。

### 7.3 后续三维地形

后续版本可以直接：

- 启用 DEM terrain。
- 开放地图倾斜和透视。
- 增加城堡、城市、森林、道路和地标三维模型。
- 保留同一地点 ID、政治边界、路线图、知识规则和旅行状态。

## 8. 地点数据模型

```ts
type MapLocationType =
  | 'region'
  | 'castle'
  | 'city'
  | 'town'
  | 'village'
  | 'port'
  | 'ruin'
  | 'landmark';

interface MapLocation {
  id: string;
  name: string;
  englishName?: string;
  type: MapLocationType;
  mapX: number;
  mapY: number;
  provinceId: number;
  baronyId?: string;
  countyId?: string;
  duchyId?: string;
  kingdomId?: string;
  regionId: string;
  terrain: string;
  isCoastal: boolean;
  isPort: boolean;
  importance: number;

```

第一版自动导入维斯特洛全部命名地点。普通地点至少拥有稳定 ID、中文名、地点类型、坐标、领地层级、地形和连接信息。

重要地点通过项目策划覆盖补充内部据点、介绍、专属图标和旅行规则。优先覆盖临冬城、君临、凯岩城、鹰巢城、奔流城、高庭、风息堡、阳戟城、派克城、龙石岛和长城主要城堡。

## 9. 权威地点引用

现有自由文本地点不再作为权威状态。人物状态拆成：

- `locationId`：地图权威地点，例如 `b_winterfell`。
- `sceneLocation`：具体场景文字，例如“神木林”。

“临冬城 · 神木林”由这两个字段组合显示。地图只将 `locationId` 视为可寻路地点。

以下系统全部改用稳定地点 ID：

- 玩家所在地。
- NPC `MOVE` 事件。
- 物品据点。
- 车辆和船只。
- 正文场景上下文。
- 世界历史地点事实。
- 活跃旅行计划。

按测试版策略提升存档版本并拒绝旧地点字符串存档，不编写旧存档兼容层。

## 10. 路线图和代价

路线图综合：

- 省份位图的真实接壤关系。
- `adjacencies.csv` 中的渡口、河流和海路。
- 道路遮罩中的道路等级。
- 地形、河流、山脉、海域和不可通行区域。
- 城堡、聚落与港口位置。

每条边至少保存：

- 起点和终点。
- 逻辑距离。
- 地形与道路等级。
- 是否渡河、渡海或经过港口。
- 允许交通方式。
- 基础时间、费用与风险。
- 季节和天气修正标签。

路线规划提供：

- 最快：时间权重最低。
- 最安全：风险权重最低。
- 最省钱：费用权重最低。
- 途经点：按玩家指定地点分段求解。

路径计算放入 Web Worker，路线图按地区分片，避免长途规划冻结界面。

## 11. 旅行状态与统一回合

```ts
interface ActiveJourney {
  id: string;
  originId: string;
  destinationId: string;
  routeLocationIds: string[];
  currentSegment: number;
  segmentProgress: number;
  mode: 'foot' | 'horse' | 'carriage' | 'ship';
  strategy: 'fastest' | 'safest' | 'cheapest';
  departureDate: WorldDate;
  estimatedArrivalDate: WorldDate;
  partyCharacterIds: CharacterId[];
  vehicleIds: string[];
  status: 'planned' | 'travelling' | 'interrupted';
}
```

### 11.1 计划和取消

地图提交的路线先进入 `planned`，尚未改变所在地。玩家可以在原地点取消。下一次成功对话由统一回合提交正式启程命令。

### 11.2 短途旅行

短途旅行可以在同一成功回合中原子执行：

- 推进日期。
- 更新人物地点。
- 移动同行车辆。
- 更新可访问资产。
- 写入世界历史事实。

### 11.3 长途旅行

长途旅行按路段推进。每次成功对话根据已确认的旅行命令推进日期和路程。旅行事件可以将状态改为 `interrupted`，但不能自行改变目的地或把失败扩大为额外灾难。

继续、停留、改道和返回都由规则层生成正式命令。AI 只叙述规则层已经确认的结果，不能自行瞬移人物。

### 11.4 人物、车辆和物品

- `partyCharacterIds` 中的同行人物随旅程移动。
- 被选中的马车和船只按实际规则移动。
- 马车内物品随车辆移动。
- 据点中未装入车辆的大件物品留在原地。
- 临时雇佣交通工具不会自动成为永久资产。

## 12. 左侧地图抽屉

### 12.1 外部行为

- 地图标签位于主界面左缘。
- 与右侧人物卷宗互斥。
- 地图关闭时暂停绘制，但保留视野、选择地点和图层状态。
- 地图加载失败时显示可恢复错误，不能阻断正文和人物卷宗。

### 12.2 内部布局

- 顶部左侧：地点搜索、当前位置、返回上一视野。
- 顶部中央：地形、政治、人物、旅行、资产地图模式。
- 顶部右侧：缩放、图层设置和关闭。
- 中央：MapLibre 地图画布。
- 内部右侧：地点详情卡。
- 底部：路线规划或旅程进度面板。
- 手机端：地点详情改为地图内部底部抽屉。

### 12.3 地图模式

默认显示地形底图和政治边界。图层可以组合：

1. 地形：山地、森林、河流、道路、海岸和聚落。
2. 政治：地区、头衔边界和公开持有人。
3. 人物：玩家已知的重要人物位置。
4. 旅行：当前路线、港口、封路和危险地区。
5. 资产：已知据点、仓库、马厩、车辆、船只和装备存放地。

### 12.4 视觉与图标

- 优先使用 AGOT 游戏二维图标。
- 无对应游戏资源时使用项目现有高质量图标库。
- 不使用 Emoji。
- 视觉延续现有羊皮纸、暗金和墨色风格。
- 地点标签优先显示中文名，详情中可显示英文原名。

## 13. 地点详情

地点详情显示：

- 名称、类型、地区和头衔层级。
- 地形、道路、港口和通行情况。
- 公开统治者，并支持打开人物卷宗。
- 玩家已知的当地人物。
- 玩家已知或可访问的据点与资产。
- 最近的已知事件。
- 从当前位置出发的预计时间、费用和风险。
- 规划路线、继续旅程或改道入口。

第一版不显示尚未实现的宣战、征服和封地建设入口。

## 14. 情报过滤

地图详情由现有知识系统和统一世界历史投影生成，不维护第二套世界事实。

情报等级：

- `confirmed`：亲眼所见、正式消息或可靠档案。
- `rumored`：只显示大致内容，不显示秘密与精确数量。
- `stale`：显示最后获知日期，并提示可能过时。
- `unknown`：不显示动态详情。

基础地形、海岸、主要道路、七国和著名城堡始终可见。以下内容必须经过知识过滤：

- 人物精确位置。
- 当前驻军和军事力量。
- 私人或隐藏资产。
- 战争、封路和危险状态。
- 秘密身份、未公开死亡和隐藏事件。

调试模式可以查看完整世界数据，但正常游戏不得使用上帝视角。

## 15. 动态政治投影

省份和头衔几何保持静态，颜色、名称和持有人从当前世界状态投影：

- 298 年初始状态来自现有头衔持有人数据。
- `GRANT_TITLE`、`REVOKE_TITLE`、死亡、继承和正式战争结果通过统一世界历史更新。
- 地图不保存独立的“当前领主”副本。
- 头衔变化后只更新受影响图层。
- 家族颜色和家徽优先使用本地游戏资源。
- 数据接口保留按历史日期重建政治状态的能力。

## 16. 性能设计

- 地形使用 512px 本地瓦片。
- 地点、边界和路线使用分级矢量瓦片。
- 地点搜索使用轻量索引，不加载全部地点详情。
- 路线图按地区分片。
- 路径计算在 Web Worker 中执行。
- 人物和资产只查询当前视野与可见情报。
- 地点图标按缩放级别聚合。
- 抽屉关闭时暂停 MapLibre 绘制。
- DEM 第一版只用于山体阴影，不启用实时三维地形。

## 17. 存档边界

正式存档保存：

- 玩家权威 `locationId`。
- 当前 `sceneLocation`。
- 活跃旅行计划及进度。
- 随行人物和车辆。
- 已知地点情报的更新时间和来源。

纯 UI 状态不进入正式世界存档，可放入本地界面设置：

- 地图缩放级别和中心点。
- 当前悬停对象。
- 临时展开面板。
- 当前图层显示偏好。

从世界历史可以推导的政治颜色、人物标记和资产列表不重复保存。

## 18. 错误处理

- 地图清单缺失时显示错误状态和重新加载入口。
- 单个瓦片失败时显示底色，不让整个抽屉崩溃。
- 地点详情失败时保持地图可操作。
- 路线不可达时给出明确原因，不生成空旅行计划。
- 存档中的地点或路线引用无效时拒绝提交该状态。
- 地图失败不能阻断正文、人物卷宗、设置或存档读取。

## 19. 数据审计

新增地图数据审计命令，验证：

- 模组源身份与必需文件。
- 省份颜色和 `definition.csv` 一一对应。
- 维斯特洛区域引用的省份全部存在。
- 每个命名地点具有唯一 ID、坐标和层级。
- 头衔、人物和地点引用可解析。
- 道路、渡口和海路连接合法。
- 不可通行山脉与海域没有进入普通旅行图。
- 只有港口能够连接普通海路。
- 所有运行时资源路径均为本地路径。
- 地形、矢量和 DEM 瓦片没有孤立文件。
- 运行时代码和清单不包含原始模组绝对路径。
- 生成数量、数据集哈希和报告一致。

## 20. 测试策略

使用小型地图 fixture 覆盖：

1. 模组地图源验证。
2. 省份颜色、像素坐标和边界提取。
3. 地理区域递归展开。
4. 王国、公国、伯爵领和男爵领层级。
5. 地点质心和策划覆盖。
6. 道路、渡口、海路和不可通行区域。
7. 最快、最安全和最省钱路线。
8. 步行、骑马、马车和乘船限制。
9. 短途单回合抵达。
10. 长途多回合推进、暂停、改道和返回。
11. 人物、车辆和物品同步移动。
12. 情报过滤和秘密防泄漏。
13. 头衔变化后的政治投影。

## 22. 第一版验收标准

第一版完成时必须满足：

- 左侧地图抽屉可稳定打开、关闭并与人物卷宗互斥。
- 维斯特洛地形、七国边界和全部命名地点可浏览。
- 地点搜索、缩放、聚合和详情正常。
- 重要地点显示策划补充资料与游戏图标。
- 人物卷宗、人物所在地、据点资产和地图使用同一地点 ID。
- 玩家可以规划最快、安全、省钱路线和途经点。
- 短途旅行可以正确结算。
- 长途旅行可以多回合推进、暂停、改道和返回。
- 日期、人物、车辆、物品和世界历史原子更新。
- 地图不会泄露玩家未知的动态信息。
- 政治地图随权威头衔状态更新。
- 所有运行时地图数据离线可用。
- DEM 和坐标协议可以直接用于后续三维地形。
- 地图失败不影响正文和人物系统。
- 地图测试、数据审计、无 Emoji 检查、TypeScript 和生产构建全部通过。

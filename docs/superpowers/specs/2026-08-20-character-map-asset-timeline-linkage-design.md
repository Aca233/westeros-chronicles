# 人物、地图、资产与时间线统一联动设计

## 目标

建立完整的“人物—地点—资产—时间线”系统，使人物卷宗、地图、资产详情、正文、旅行、装备与世界历史读取同一份当前世界事实。任何有效世界变化都必须经过统一验证和原子提交；任何界面都不得根据静态资料、模型措辞或另一组件的局部状态自行猜测结果。

本设计覆盖：

- 人物所在地、旅行状态、生死与头衔；
- 伯爵领政治归属和实际控制；
- 城堡、城市、村庄、庄园与仓库；
- 马车、船只及其承载内容；
- 装备、普通物品、书籍、药物、首饰与家传物品；
- 玩家输入中的直接或隐含地点变化；
- 人物、地点和资产关联事件；
- 正文解析、叙述与 LLM 上下文。

不提供全局历史日期检视。界面只显示当前世界状态，以及人物、地点和资产各自的事件记录。

## 已确认的领域规则

### 五类关系严格分离

每项资产根据类型保存以下关系：

1. **法理归属**：名义上属于人物、家族或头衔。
2. **实际控制**：当前能够支配、使用、征税或调动该资产的主体。
3. **直接保管**：当前直接看管可移动资产的人物、据点或车辆。
4. **物理位置**：人物、地点或容器；容器内资产的位置通过容器递归解析。
5. **装备状态**：只有明确穿戴或持用时才存在装备位置。

占领据点只改变控制，不自动改变法理归属；偷窃只改变保管和位置，并保留原法理所有者；正式赠予、继承、册封或剥夺才改变法理归属。

### 确定性连锁由程序执行

LLM 只声明已经发生或意图发生的高层事实，不逐项同步派生状态。程序负责：

- 人物旅行时同步移动同行者；
- 车辆移动时通过容器关系同步其内部资产位置；
- 正式头衔转移时同步人物头衔和地图法理归属；
- 据点被占领时只改变控制和访问权限；
- 赠礼时同步法理归属、保管与位置；
- 偷窃时保留法理归属并生成失窃状态；
- 人物死亡时卸下装备，将随身物品留在死亡地点，并把法理资产置为待继承；
- 同一事务失败时撤销全部派生变化。

## 架构选择

采用“统一当前状态 + 不可变事件记录”的混合架构。

不继续让人物、地图和资产系统分别修改后相互同步；也不要求通过重放全部历史事件计算当前世界。当前状态用于快速读取，不可变事件用于人物经历、地点近期事件、资产沿革、总时间线和正文事实。

```text
开局静态数据
  ├─ AGOT 人物与头衔
  ├─ 地图地点与层级
  ├─ 据点和车辆
  └─ 物品与初始资产关系
            │
            ▼
BaselineWorldRepository
            │
            ▼
WorldRuntimeState（仅保存动态覆盖）
            │
            ├─ WorldProjection → 人物卷宗
            ├─ WorldProjection → 地图
            ├─ WorldProjection → 资产详情
            ├─ WorldProjection → LLM 上下文
            └─ WorldEvent → 时间线与对象沿革
```

所有世界变化走同一条管线：

```text
玩家输入或界面操作
→ WorldIntent 语义解析
→ 稳定 ID 解析
→ WorldTransaction 构建
→ 规则验证
→ 确定性连锁计算
→ 原子提交 WorldRuntimeState
→ 追加 WorldEvent
→ 受影响投影失效并重新计算
```

## 与现有系统的关系

### 保留并演进

- `worldHistory` 的回合账本、原作节点和先结算后叙述流程继续保留，其事实模型演进为统一 `WorldEvent`。
- `characterEventStore` 的人物事件能力并入统一事件索引；人物卷宗不再拥有独立事实来源。
- 地图旅行的路线规划、地形成本和旅程推进继续复用，提交结果改为世界事务。
- `WorldArtifactState` 继续作为离线生成的开局资产基线，运行时变化写入 `WorldRuntimeState.assets`。
- 物品目录、装备合法性、容量、耐久、次数等物品领域逻辑继续保留。

### 消除并行权威

- 人物所在地不再同时由玩家资料、人物事件和地图临时状态分别决定。
- 资产关系不再同时存在于玩家物品栏、NPC 装束、世界物品和据点容器中而缺少统一解释。
- `ItemSystemState` 只负责物品的内在状态，如数量、耐久、次数和容量规则；所有权、控制、保管、位置与装备关系以 `WorldRuntimeState` 为权威。
- UI 组件不直接写入人物、地图或资产状态，只提交待处理世界事务。

测试版直接提升存档结构版本，不迁移旧存档。

## 统一运行时模型

```ts
interface WorldRuntimeState {
  schemaVersion: 1;
  revision: number;

  characters: Record<CharacterId, CharacterWorldPatch>;
  titles: Record<TitleId, TitleWorldPatch>;
  assets: Record<AssetId, AssetWorldPatch>;

  events: WorldEvent[];
  pendingTransactions: PendingWorldTransaction[];
}
```

`revision` 每次成功事务递增一次，用于投影缓存和幂等检查。未发生变化的对象不进入对应动态字典。

### 人物动态覆盖

```ts
interface CharacterWorldPatch {
  alive?: boolean;
  location?: WorldLocationRef | null;
  currentActivity?: 'idle' | 'travelling' | 'imprisoned' | 'missing';
}
```

没有动态覆盖时，从 AGOT 离线人物资料、开局头衔和开局地点读取基线。人物实体不复制姓名、文化、信仰、特质等静态卷宗字段。人物当前头衔从头衔状态按 `lawfulHolderId` 反向投影，不在人物覆盖中重复保存。

### 头衔动态覆盖

```ts
interface TitleWorldPatch {
  lawfulHolderId?: CharacterId | null;
  controllerId?: CharacterId | null;
  contestedByIds?: CharacterId[];
}
```

- 伯爵领及以上头衔使用法理持有人和实际控制者。
- 战争占领、叛乱或临时军事控制只改变 `controllerId`。
- 继承、册封、正式战争结算、剥夺和退位可以改变 `lawfulHolderId`。
- 城堡、城市和村庄作为地点资产关联所属伯爵领，不恢复男爵领政治操作层级。

### 资产动态覆盖

```ts
interface AssetWorldPatch {
  kind: 'item' | 'site' | 'vehicle';

  lawfulOwner?: SubjectRef | null;
  controller?: SubjectRef | null;
  custodian?: SubjectRef | null;

  placement?: AssetPlacement | null;
  equippedPosition?: EquipmentPosition | null;

  status?: 'normal' | 'stolen' | 'contested' | 'inheritance_pending';
}
```

`SubjectRef` 可以引用人物、家族或头衔。`AssetPlacement` 可以引用人物、地图地点、据点或车辆容器。

动态覆盖字段遵循统一三态语义：字段缺失表示继续使用静态基线，`null` 表示明确清除当前关系，具体值表示替换基线。这样可以表达头衔空缺、资产无人保管和卸下装备，而不会把“没有覆盖”误当成“关系不存在”。

位置规则：

- 物品位于人物身上时，地图位置由人物所在地解析。
- 物品位于车辆中时，地图位置由车辆所在地解析。
- 物品位于据点时，地图位置由据点关联地点解析。
- 据点位置来自地图基线，不随控制者移动。
- 容器关系必须无环；同一资产只能有一个直接位置。
- `equippedPosition` 存在时，直接位置必须是对应人物，且该人物必须是直接保管者。

### 世界事件

```ts
interface WorldEvent {
  id: string;
  transactionId: string;
  turn: number;
  date: WorldDate;
  type: WorldEventType;

  actorIds: CharacterId[];
  subjectRefs: WorldSubjectRef[];
  location?: WorldLocationRef;

  reason: string;
  source: 'player_input' | 'ui_action' | 'ai_resolution' | 'system_rule';
}
```

事件只保存一次，通过人物、地点、资产和头衔索引投影到各界面。`WorldTurnRecord` 继续作为一次回合结算的外层记录，通过 `transactionId` 和事件关联。失败或取消的事务不生成“已发生”事件。

## 稀疏动态状态

项目包含约 11,450 名人物，运行时不预先为所有人物创建完整状态。

- 未参与剧情的人物继续使用离线开局资料。
- 人物、头衔或资产第一次发生移动、交易、战争、继承、伤病或其他变化时才创建动态覆盖。
- 当前状态由“静态基线 + 动态覆盖”投影，不通过重放全部历史计算。
- 地图只加载当前视野、选中伯爵领和当前剧情相关的人物与资产。
- LLM 只接收当前地点、邻近地点、参与人物、可访问资产和近期相关事件。

## 玩家输入与隐含地点变化

### 语义意图

规则解析阶段先生成高层语义，不直接写零散状态命令：

```ts
interface WorldIntent {
  kind:
    | 'mention'
    | 'plan_travel'
    | 'start_travel'
    | 'advance_travel'
    | 'arrive'
    | 'move_inside_location'
    | 'transfer_asset'
    | 'equip_asset'
    | 'change_title_control'
    | 'change_title_ownership';

  actorId: CharacterId;
  targetRef?: WorldSubjectRef;
  elapsedTime?: WorldDateAdvance;
  evidenceText: string;
}
```

`evidenceText` 保存触发意图的玩家原文片段，用于审计。程序不能仅凭出现地点名称就移动人物。

### 地点语义分类

- “我想起了君临”：`mention`，不改变位置。
- “我想去君临”：愿望，不自动移动。
- “我准备明日去君临”：`plan_travel`，生成计划但未出发。
- “我骑马赶往君临”：`start_travel`，建立并开始路线。
- “三日后越过红叉河”：`advance_travel`，推进旅程。
- “半个月后抵达君临”：`arrive`，验证路线和最低耗时后完成旅程。
- “我已经到了君临”但没有现有旅程或足够时间：识别为抵达声明，但验证器拒绝瞬移。
- “我从大厅走进神木林”：在同一地图地点内更新 `sceneLocation`。
- “推开临冬城大厅的门，我向艾德行礼”：主要行动是交谈，但解析器仍提取附带地点事实并验证。

地点名称通过地图别名、当前位置、邻近伯爵领和当前剧情映射为稳定 `locationId + sceneLocation`。无法唯一解析时保留其他主要行动，但拒绝地点变化。

### 跳时抵达

玩家明确表达时间流逝和已抵达时，允许系统自动计算最低旅行时间：

1. 从权威当前位置规划合法路线。
2. 根据地形、交通工具、同行者和旅行状态计算最低耗时。
3. 声明时间足够时生成出发、推进和抵达的单一原子事务。
4. 声明时间不足时不能瞬移；只推进到合法的途中位置或保留未开始状态，取决于输入是否明确出发。
5. 普通“我去君临”只开始旅行，不自动跳过全部路程。

## 待处理操作与原子事务

所有改变世界的 UI 操作进入 `pendingTransactions`，包括：

- 穿戴与卸下；
- 赠礼、转移、偷窃与放入容器；
- 携带马车、登船和选择同行者；
- 开始、暂停、改道或取消旅程；
- 其他需要下一次成功对话确认的世界操作。

查看、搜索、界面切换和跨页面跳转立即生效，不进入队列。

```ts
interface PendingWorldTransaction {
  id: string;
  status: 'pending' | 'committed' | 'rejected' | 'cancelled';
  source: 'ui_action' | 'player_input';
  intents: WorldIntent[];
  rejectionReason?: string;
}
```

队列规则：

- 操作入口原位置显示“取消”，不增加独立全局取消条。
- 同一资产或同一互斥槽位的新操作替换或取消旧操作。
- 下一次成功对话后，UI 队列和自然语言意图一起进入结算。
- 重复提交同一事务 ID 不会重复移动、赠予或推进时间。
- 验证失败时不写入当前状态，也不生成已发生事件。

### 原子提交

“玩家乘马车带琼恩和寒冰抵达临冬城”必须在一笔事务中完成：

1. 推进世界日期；
2. 移动玩家；
3. 移动琼恩；
4. 移动马车；
5. 通过容器关系解析车内物品的新位置；
6. 保持寒冰的法理归属、控制、保管和装备状态语义；
7. 追加人物、地点、车辆和资产关联事件。

任一步失败，全部变化不提交。

## 验证规则

事务提交前必须通过以下检查：

- 所有人物、地点、头衔和资产 ID 存在。
- 行动人物存活，且未处于不允许行动的状态。
- 转移双方、目标容器或相关地点处于可接触范围。
- 赠予由实际控制者发起；偷窃允许非所有者发起，但不能伪造法理归属。
- 装备物品由人物直接保管，位置和槽位兼容。
- 容器无环，容量足够，同一资产没有重复位置。
- 路线连续，地形和交通工具合法，时间不短于可达下限。
- 正式头衔变更具有继承、册封、剥夺、退位或正式战争结算依据。
- 同一事务中的多条意图不存在相互矛盾的最终状态。

验证器输出结构化失败原因。事务只有完整成功或完整失败，不允许人物已移动而车辆仍在原地等半提交状态。

## 投影与界面联动

### 人物卷宗

- 顶部所在地来自当前世界投影，点击后打开地图并定位。
- 头衔同时展示法理持有和实际控制冲突。
- “健康与装备”只显示真实伤病和当前实际穿戴。
- “物品与资产”按当前携带、本人保管、名下异地资产、实际控制资产、领地资产和运输资产分组。
- 资产条目显示所在地、保管者、控制者和所有者；人物与地点均可点击跳转。
- 经历页面显示与该人物关联的移动、赠予、失窃、占领、继承、装备和伤病事件。
- 玩家与 NPC 使用同一投影与同一视觉语义。

### 地图

- 仍以伯爵领为主要政治交互单位。
- 政治填色来自法理持有人；占领或争议通过控制描边表达。
- 点击伯爵领显示法理领主、实际控制者、当前重要人物、地点资产、车辆、重要物品和近期事件。
- 点击人物打开人物卷宗；点击资产打开资产详情；点击事件打开关联对象。
- 人物移动后，地图标记、人物所在地和正文上下文读取同一投影结果。
- 未处于当前视野或剧情范围的大量普通人物不生成标记。

### 资产详情

统一显示：

- 类型与物品定义或地点定义；
- 法理所有者；
- 实际控制者；
- 直接保管者；
- 直接位置和解析后的地图位置；
- 装备位置；
- 正常、失窃、争议或待继承状态；
- 最近取得、转移、失窃、占领和使用记录。

物品、据点、马车和船只使用相同关系语义，但按类型隐藏不适用字段。

### 时间线

- 不提供历史日期模式。
- 总时间线展示本世界已经发生的事件和原作预定压力。
- 人物、地点、资产和头衔页面只筛选自身关联事件。
- 事件中的人物、地点、头衔和资产可以点击跳转。
- 时间线是只读投影，不能反向修改当前世界状态。

## 正文和 LLM 上下文

每次规则解析和叙述只注入与当前行动相关的世界切片：

- 当前地点、内部场景、所属伯爵领和邻近地点；
- 当前场景人物及其权威所在地；
- 当前人物实际穿戴、携带和直接可用物品；
- 当前地点可访问的据点、车辆和资产；
- 法理归属与实际控制冲突；
- 当前旅程、同行者与待处理事务；
- 最近相关事件和到期原作压力。

LLM 不接收全部人物和地图数据，也不能把未知资产、静态保管关系或玩家单方面声明当作已发生事实。规则解析只输出意图；最终正文只接收程序已经提交的事务与事件。

## 错误处理

- 地点无法唯一解析：保留其他主要行动，拒绝地点变化。
- 旅行声明耗时不足：不允许直接抵达，按合法进度处理。
- 保管、位置或装备关系冲突：拒绝整笔事务并显示冲突对象。
- 静态资料引用缺失：对象页面显示“资料未能解析”，不让整个人物卷宗或地图崩溃。
- 事件包含已删除或未知对象：跳过该关联并记录审计错误，不伪造对象。
- 事务重复：按稳定事务 ID 幂等处理。
- 叙述生成失败：已结算状态保持不变，允许重新生成叙述但不重复结算。

## 性能设计

- 动态状态只保存发生变化的对象。
- 建立人物、地点、资产和头衔到事件 ID 的反向索引。
- 建立地点到当前人物、车辆和据点资产的当前状态索引。
- 容器地图位置按 `WorldRuntimeState.revision` 缓存。
- 一次事务只使受影响对象的投影缓存失效。
- 地图按当前视野和选中伯爵领按需读取。
- 人物卷宗只加载当前人物及其直接关联资产和事件。
- LLM 上下文对人物、资产、事件和邻近地点设置独立数量预算。
- 性能审计禁止地图交互遍历全部 11,450 名人物或全部资产。

## 测试策略

### 数据模型测试

- 法理归属、控制、保管、位置和装备互不混淆。
- 容器无循环，同一资产没有重复位置。
- 静态基线与动态覆盖得到稳定投影。

### 事务测试

- 赠礼、偷窃、占领、册封、继承、死亡和装备。
- 失败事务不留下部分状态。
- 重复事务保持幂等。
- 确定性连锁不依赖 LLM 逐项命令。

### 旅行与语义测试

- 地点提及、愿望、计划、出发、途中、抵达和内部场景移动。
- 明确跳时抵达会计算最低耗时。
- 隐含地点事实能够提取，但普通地点提及不会移动。
- 同行人物、车辆和容器内资产同步移动。

### 跨界面集成测试

一次事务后，以下投影必须一致：

- 人物卷宗所在地和资产关系；
- 地图人物标记、政治控制与地点详情；
- 资产详情；
- 世界时间线和对象沿革；
- 下一回合 LLM 世界上下文。

### 性能与数据审计

- 未变化人物不进入动态状态。
- 地图当前操作不遍历全部人物和资产。
- 事件索引无孤立 ID。
- LLM 上下文大小有明确上限。
- 开局静态数据中的人物、地点、头衔和资产引用全部可解析。

## 实施边界

该架构按一个总计划、四个可独立验收的里程碑实施：

1. 建立统一模型、基线仓储、事务归约器和投影接口，并用适配器接入现有状态。
2. 接入人物移动、旅行、车辆、容器资产、装备和待处理操作。
3. 接入头衔、伯爵领政治控制、据点资产以及人物—地图—资产互相跳转。
4. 接入自然语言隐含意图、统一 LLM 世界切片、时间线索引和全量性能审计。

每个里程碑完成后必须运行跨界面一致性测试；后续里程碑不得重新引入平行状态权威。

## 验收场景

### 隐含抵达

玩家在临冬城输入：“半个月后，我推开红堡议事厅的门，向国王行礼。”

- 解析主要行动“行礼”和附带事实“半个月后抵达红堡议事厅”。
- 解析红堡稳定地点与内部场景。
- 验证路线、交通方式和最低耗时。
- 时间足够时原子推进日期、人物、同行者、车辆和资产。
- 地图定位君临，人物卷宗显示红堡议事厅，正文只叙述已提交事实。

### 占领但未获封

军队占领某伯爵领：

- 地图保留原法理领主颜色。
- 增加实际控制描边和争议状态。
- 据点控制者改变，法理所有者不变。
- 原领主和占领者卷宗都出现关联事件。
- 只有正式战争结算或册封后才改变法理持有人。

### 失窃资产

人物从城堡仓库偷走一把家传剑：

- 剑的法理所有者不变。
- 保管者和物理位置改为偷窃者。
- 状态标记为 `stolen`。
- 城堡、所有者、偷窃者和资产详情引用同一事件。
- 偷窃者未明确装备时，健康与装备页面不显示该剑。

### 人物死亡

人物在旅途中死亡：

- 人物变为死亡状态并停止旅程。
- 实际装备被卸下并留在死亡地点或对应车辆容器。
- 法理资产进入待继承状态。
- 地图、人物卷宗、资产详情和时间线同步显示结果。
- 继承由后续确定性继承事务处理，不由叙述模型随意分配。

## 非目标

- 不提供任意历史日期的世界状态回放。
- 不恢复男爵领作为政治地图的主要操作层级。
- 不在浏览器运行时读取 Steam、Workshop、CK3 或 AGOT 文件。
- 不让 LLM 自行维护资产清单、路线或政治归属。
- 不为全部人物持续模拟日常行为。
- 不实现旧测试存档迁移。
